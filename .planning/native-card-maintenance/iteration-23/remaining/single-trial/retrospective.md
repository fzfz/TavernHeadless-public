# 单次转换复盘

## 1. 测试范围和结果

1. 主代理仅派发过一名使用干净上下文的队员，派发消息仅包含 Skill 和单个 JSON 文件。执行期间没有追加指导；派发见 [dispatch.json](dispatch.json)。
2. 主代理按13项源行为检查记录6项通过、3项失败、4项未执行，整卡失败。逐项结论和检查范围见 [main-acceptance.json](main-acceptance.json)。
3. 包格式通过，最终 ZIP 与155个包文件一致，正式导入和155个文件回读通过。证据见 [package-preservation.json](package-preservation.json)、[formal.json](formal.json)和[readback.json](readback.json)。
4. 默认正式会话创建返回500，模块资源超过128文件限制；页面、历史、发送锁、解锁、失败恢复、状态请求和真实模型检查未执行。证据见[默认预览失败](default-preview-failure.json)。
5. 队员随后修改应用配置，将上限改为256。主代理中止队员及对应预览进程，退出处理恢复了测试前的配置原文。只读边界判为失败；临时条件下的请求不计入默认系统通过。证据见[边界记录](termination-and-boundary.json)。

## 2. 耗时与调用

1. 会话启动至中止共55分14秒，宿主工具调用214次，上下文压缩2次。首次包登记在启动约39分钟后；正式打包在约49分钟后。20分钟文件生成目标和30分钟离线目标均失败，计时见[执行统计](execution-summary.json)。
2. 前约20分钟包含资料读取、条目写入路径错误、误判批量成功、读取旧产物及重新写入。随后约19分钟用于开场、状态配置、控制器和前端生成。首次登记至打包约10分钟，主要用于修正模块接口与格式。最后约6分钟用于预览配置、容量错误排查及临时修改应用配置。
3. 首次133条目批量写入均返回路径错误，队员将缺失的 `issues`、`remaining` 计为零，误报成功；压缩摘要继承了这个误报。队员自行发现并改用相对路径重做。原始错误与恢复见[观察记录](observations.json)。
4. 会话累计输入29,061,086 tokens，其中缓存输入28,372,992 tokens；输出154,073 tokens。实际费用未记录。统计不包含主代理后续验收。

## 3. 转换问题与根因

### 3.1. 输入来源和只读范围

1. 队员读取并复制了 `apps/web/prototypes/characters/linqian` 的旧卡、schema、规则、derive 和 validate。
2. Skill 指明了单个输入文件与只读资料，但没有明确排除旧试产卡和旧转换产物；队员主动把它们作为转换依据。修改应用配置则违反了包目录和任务目录的写入范围。

### 3.2. 工具调用与 API 使用

1. map-entry 正确拒绝绝对目标路径；错误来自队员传参和批量结果统计。当前失败诊断集中在工具文档末节，Skill 的 begin 节单独说明了 `error`，其他写入步骤未明确引用共同的失败处理。
2. 队员复制的旧模块使用不支持的 Date、structuredClone、导出和导入方式，首次正式校验返回22项问题。修复后包校验通过。

### 3.3. 规则生效条件

1. 源条目105禁用扫描，由控制器在 E032=true 时载入。目标状态规则文件始终包含该条目，并将其来源状态写为“启用”。
2. 目标 derive 仅依据模型给出的 `routeRulesLoaded` 接受路线变化，没有保留 E032 条件。主代理用 E032=false 复现了路线变化，证据见[规则样例](route-rule-result.json)。
3. 条目105、110的规则原文已经保存。25组控制器样例与源模板输出、引用条目一致，其中4组终局样例修复了此前 E048 抢占的问题，见[控制器结果](controller-results.json)。

### 3.4. 删除遗漏和文字改写

1. 108、109的旧输出协议仍作为条目保存；配置将它们排除于正文提示，但109的业务约束没有进入所配状态规则文件。
2. 目标前端重新编写 HTML 和 CSS，源状态栏的两段 CSS 均未原样保存，原文保存验收失败。
3. 两个开场的剧情文本为源字段的连续原文，初值保留了各自差异。

## 4. 系统容量与未执行项

1. 当前加载器收集全部 server_script 及 data JSON，本包共148份模块资源，其中133份为世界书条目。移除初始化条目2、旧协议108、109及已转存规则110后，仍有144份，超过128上限。
2. 该计数包含模块没有导入的世界书文件。
3. 本次未取得正式状态更新请求和真实模型输出。规则生效条件、删除遗漏与原文改写已有转换证据；不能将这些问题归因于真实模型理解。
