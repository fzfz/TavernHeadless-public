# 提示词组装现状与改动建议对照

## 1. 总目标

1. 本文根据[现状调研](prompt-assembly-research.md)评估状态任务接入，明确每项建议修改的对象、理由及对应方案位置。
2. 本文中的“保留”“调整”“新增”描述建议动作；各项动作由[架构方案](architecture-proposal.md)规定实施方式。

## 2. 现状调研

1. 正文调用链及实际数据来源见《现状调研》第2、3节。
2. 组装模式、节点、预算和消息处理见《现状调研》第4至8节。
3. 状态任务当前消费的数据、模型绑定和提交链见《现状调研》第9节。
4. 调研覆盖范围见《现状调研》第10节。

## 3. 面临的问题

| 编号 | 当前事实的依据 | 接入状态任务时面临的问题 |
| --- | --- | --- |
| P1 | 现状调研第2.3、9.1节 | 两类任务的请求由不同入口构建，状态请求尚未接入系统预设和完整组装流程 |
| P2 | 现状调研第7.1、9.1节 | 共享输入表达当前用户消息，状态任务需要表达成功保存的本轮消息序列 |
| P3 | 现状调研第9.3节第2、3项 | 组装器解析的变量与状态计算前值具有不同来源，重算需要使用原计算前值 |
| P4 | 现状调研第3、9.2节第1项 | 正文已经接入的数据来源尚未作为完整组装数据提供给状态任务 |
| P5 | 现状调研第9.1节 | 状态任务已经消费本轮来源和前值，尚未读取前 n 轮变量更新记录 |
| P6 | 现状调研第8.1、9.1节 | 状态任务的任务指令来自 updaterPrompt，需要与管理员编辑的状态预设衔接 |
| P7 | 现状调研第9.2节第2至4项 | 世界书条目用途和独立规则文件的对应关系需要在转换产物中明确 |

## 4. 解决和实施方案

### 4.1 建议调整和新增的接入

| 对应问题 | 建议动作 | 改动对象 | 建议理由 | 方案位置 |
| --- | --- | --- | --- | --- |
| P1 | 调整 | StateUpdateService 调用共享 assemblePrompt | 状态请求可使用管理员配置的预设和系统组装流程 | 架构方案第4.3.1、4.5.2节 |
| P2 | 调整 | 共享输入分别接受历史消息和本轮消息序列，并同步宏、扫描及注入坐标消费者 | 本轮成功回复可以按其实际角色和顺序参与状态判断 | 架构方案第4.3.2节 |
| P3 | 调整 | 共享变量上下文接受本次状态计算使用的 stat_data | 状态请求中的变量宏与后端计算使用同一前值 | 架构方案第4.3.2节 |
| P4 | 新增 | 状态任务接入角色、人设、世界书、记忆、历史、状态投影和附加内容的数据来源 | 管理员可以按角色需要选择判断变量所需的资料 | 架构方案第4.2.1节 |
| P5 | 新增 | 按 n 准备独立变量历史数据源 | 状态模型可以读取已提交的逐轮变量变化 | 架构方案第4.2.3节 |
| P6 | 新增 | 发布、试聊及会话固定配置增加状态预设引用和变量历史轮数 | 管理员可以编辑、选择和调试状态任务预设 | 架构方案第4.5.1节 |
| P7 | 调整 | 转换产物记录有效规则资源，状态预设通过规则数据源读取原文 | 源规则的条件、数值、例外和关联资料有明确消费者 | 架构方案第4.3.3节 |
| P1、P6 | 新增 | 状态预览与正式调用使用同一数据准备和组装入口 | 管理员能够查看正式状态请求采用的消息和组装追踪 | 架构方案第4.5.2节 |

### 4.2 建议保留的现有处理

| 处理对象 | 建议动作 | 建议理由 | 现状依据与方案位置 |
| --- | --- | --- | --- |
| 预设节点及组装模式 | 保留现有启用、触发、位置、顺序、宏及模式处理 | 管理员继续使用现有预设编辑和调试方式 | 现状调研第4、5节；架构方案第4.3.1节 |
| 提示词预算和裁剪 | 保留现有算法；n 用于变量历史数据读取 | 聊天历史组装和变量历史准备分别由其对应流程负责 | 现状调研第6.1节；架构方案第4.2.3、4.3.1节 |
| 模型绑定 | 保留现有状态模型绑定及参数解析 | 本次接入修改提示词来源，管理员已绑定的变量更新模型继续承担该任务 | 现状调研第9.1节；架构方案第4.1、4.4节 |
| 规则全文读取 | 保留 ruleFiles 的原文读取 | 模型继续取得角色作者的完整更新规则 | 现状调研第9.1节；架构方案第4.2.2节 |
| 正文投影与工具证据 | 保留正式来源读取和证据校验 | 状态判断继续使用成功正文及其实际接受的执行结果 | 现状调研第9.3、9.4节；架构方案第4.3.3、4.4节 |
| 提案、派生、校验和提交 | 保留现有处理顺序及恢复入口 | 状态任务继续通过正式提交链保存变量和显示快照 | 现状调研第9.3、9.4节；架构方案第4.4节 |
