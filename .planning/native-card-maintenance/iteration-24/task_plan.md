# 单卡转换改进实施

## 1. 总目标

1. 主代理执行 iteration-23/remaining/next-iteration-plan.md 第4章，交付修订后的 Skill、按实际依赖加载的后端、单次转换及正式运行验收结果。
2. 主代理分别记录转换正确性、转换耗时、验收耗时和维护总耗时，并精确提交本次文件。

## 2. 现状调研

1. 当前分支为 codex/native-card-converter-design，HEAD 为 ddbfbea；main 和独立状态预设预览适配已接入。
2. 工作区保留54份既有修改；初始文件名单和补丁位于 execution.json 与 initial-diff.patch。
3. 加载器目前收集全部后端 JS 与 data JSON；此前测试 ZIP 有155个文件，其中148个被计数，包含133个世界书条目文件。

## 3. 面临的问题

1. 后端脚本运行额度计入未被脚本导入的世界书文件。
2. Skill 内置状态 API 尚未完成同步，条件规则和纯正文变量格式要求需要修订。
3. 单卡转换曾读取其他卡的产物并修改系统配置；本次须依据实际操作核对边界。

## 4. 解决和实施方案

1. 已完成：队员修复 RoleModuleLoader 的入口及静态依赖收集，覆盖合法依赖、超限及拒绝分支；额度保持原值。
2. 已完成：队员同步状态 API、schema、架构和格式入口；主代理已修订通用语义规则及通用示例。
3. 已完成：工具联调及独立文档审计完成；一次干净上下文转换已结束。
4. 已完成：主代理验收原始ZIP及修复副本。原始13项检查为5项通过、6项失败、2项未执行；修复副本正式导入、回读与状态dry-run通过，实际状态模型调用失败。
5. 进行中：耗时及正确性复盘、code-review和最终全量检查已经完成；主代理正在审计最终报告并精确提交。

## 5. 方案待决策项清单

1. 当前没有待批准事项。若本次验收发现新 API 缺口，主代理保存实际请求后提出具体扩充方案。

## 6. 计划验收清单

1. 未导入文件不占模块额度；入口和传递依赖可运行；真实依赖超限、动态或外部导入、非法路径被拒绝。
2. Skill 内置状态资料与正式实现一致，条件规则按正式状态提示组装生效。
3. 转换仅读取本次源卡及允许的只读依据，仅写入该次输出目录，交付原生 ZIP。
4. 主代理逐项记录源文保留、删除决定、程序分支、包校验、导入、回读和核心运行结果，区分通过、失败与未执行。
5. 主代理以宿主实际时间记录阶段耗时，按原方案的20分钟生成和30分钟转换目标判定效率。
6. 项目检查及独立审阅完成，本次文件已提交，既有修改保留。

1. 本次不扩充包自定义工具，不修改系统运行额度，不执行独立手机会话或原子存档恢复卡。
2. 本次完整转换只测试一张卡；其余117项维护任务保留在原维护计划。
