# 角色卡转换CLI改进方案

## 1. 总目标

1. 维护执行者修改全部转换命令及独立服务入口，使Agent在预检后直接阅读待判断原文，通过文件路径取得完整命令结果，并发读取源卡和写入不同目标文件。
2. 每个命令提供用途、参数、示例和可执行的错误修正方法。程序支持标准输入管道，使用正确的数据通道及退出码，并防止重试产生重复资源或丢失字段。

### 1.1. 必须遵守的CLI最佳实践

1. 维护执行者对全部转换命令和独立服务入口执行用户规定的七条最佳实践，具体实施规则及验收位置如下。

   | 最佳实践 | 实施规则所在章节 | 对应验收项（第6章） |

## 2. 现状调研

### 2.1. 检查范围

1. Skill入口为`.agents/skills/native-card-conversion/scripts/convert.mjs`。它自行分派部分命令，其余命令交给`scripts/native-card-conversion/cli.ts`。
2. 检查覆盖下表全部命令，以及`preview.ts`、`replay-fixture.ts`的独立启动入口。
3. 复现程序为[reproduce.mjs](reproduce.mjs)；字节统计及并发结果见[检查结果](check-results.json)。本次未启动正式导入、预览和回放服务，相关发现来自源码检查。

### 2.2. 命令检查结果

1. 各命令的输出和文件行为如下。

   | 命令 | 当前输出 | 当前多次调用及并发行为 |
   | --- | --- | --- |
   | `begin` | 完整`written`、`pending`、`issues`进入stdout；样本501402字节。单条匹配摘录也会随源文本增长。 | 每次创建新任务；创建中断可留下部分目录。 |
   | `read` | 成功返回正文与行位置文件路径；长正文样本338字节。 | 同一任务使用固定文件名。八个并发提取返回同一个正文路径，最后全部读到同一份值；正文与行位置分别替换，可能不对应。 |
   | `map-entry` | 单条返回诊断和剩余字段；80条批量结果28250字节。 | 多个调用会读取、合并并替换同一目标文件。批量逐条重新解析源卡并计算整本世界书UID。 |
   | `map-regex` | 完整诊断和剩余字段进入stdout；样本1019521字节，有问题仍退出0。 | 整个目标数组覆盖写入；同一文件并发请求以最后写入为准。 |

   | `parse` | 成功输出较小；JSON或YAML解析诊断可很长。 | 使用与`copy`相同的目标文件写入方式，具有相同的字段丢失风险。 |
   | `index` | 完整包诊断进入stdout；样本1887456字节，有问题仍退出0。 | 扫描包后替换固定manifest；与包写入同时执行时，可能扫描到临时文件或前后不一致的文件集合。 |
   | `validate` | 已保存完整结果，但stdout仍输出前20条诊断；单条诊断没有字节限制。 | 结果目录独立；包扫描与写入没有协调。 |

   | `resume` | 输出任务信息及完整目录列表，列表长度未限制。 | 不写文件；目录列表可能包含尚未完成的产物。 |
   | `formal` | 保存完整证据，同时输出请求列表、诊断及回读结果，长度未限制。 | 每次使用独立运行目录，但共享父目录的首次创建有竞争；CLI读取固定`role.zip`。 |
   | `preview` | 启动输出包含dry-run列表，停止输出包含回放错误数组；独立入口错误输出完整堆栈。 | 运行目录、端口已有隔离；CLI仍读取固定`role.zip`。现有测试已覆盖部分多实例清理及环境变量恢复。 |
   | `replay-fixture` | 启动信息较小；停止错误列表及独立入口堆栈长度未限制。 | 同一指定目录的多个实例追加同一日志、覆盖同一summary；监听后保存summary失败的路径缺少服务关闭。 |

### 2.3. 公共实现

1. `source.ts`的`printResult`直接输出完整JSON；`cli.ts`仅截取部分顶层诊断。两条输出路径没有统一控制。
2. `atomic-write.ts`通过临时文件和rename替换单个文件，但没有保护完整的读取、修改和写回过程；临时文件位于包内，包扫描器会读取它们。
3. 入口读取`process.argv`，没有stdin协议和逐级帮助。缺参数及未知命令的实测均为退出1、stderr为空、错误JSON进入stdout。
4. 既有输出和归档发布测试共18项通过；这些测试未覆盖本次复现的并发字段丢失和超长诊断。

## 3. 面临的问题

1. 长结果从多条出口进入终端；只限制诊断条数不能避免截断。成功结果、失败详情和服务关闭错误均需要处理。
2. 提取使用共享文件名，多个Pointer需要多次调用；长单行内容即使保存为文件，直接读取仍可能被宿主截断。
3. 单文件原子替换不能保护JSON字段合并；扫描和写入并行时，校验对象也可能变化。
4. 正式导入及预览没有绑定调用者选中的独立ZIP，可能使用下一次打包的内容。
5. CLI缺少管道、帮助和明确的修正命令；部分失败使用成功退出码，错误写入正常数据通道。
6. 创建任务或服务的重试没有调用标识，多次执行会创建额外资源；独立回放还存在日志混用和失败后监听残留。

## 4. 解决和实施方案

### 4.1. 拟实施的转换架构

1. 脚本路径相对于Skill目录。字段处理和命令调用规则见第4.3、4.4节。

2. 关联原文的补读命令`node scripts/convert.mjs extract`见第4.4.7节；命令失败的诊断和退出规则见第4.2节。

### 4.2. 统一结果文件和数据通道

1. 维护执行者修改`output.ts`，增加所有入口共用的结果保存函数。每次调用在任务的`calls/call-<随机ID>/`创建独立目录；尚未取得有效任务的调用在仓库`.tmp/native-card-conversion/calls/`下创建目录。目录由脚本创建。
2. 完整结果统一写入`result.json`。成功时stdout通过`resultFile`引用该文件；失败时stderr通过`diagnosticFile`引用该文件，stdout为空，退出码非零。终端同时返回文件字节数，文件的公共字段包括命令名称、实际成功状态和命令结果`data`；各命令在`data`中定义自身返回值。
   输出函数按命令返回的`passed`及执行异常决定退出码。`begin`完成预检及内容保存后返回`passed: true`，源字段修正事项按第4.4.4节处理；输入读取、解析或文件保存失败时返回`passed: false`。映射、索引及包检查命令在目标格式检查失败时返回`passed: false`。写入命令中的`remaining`表示该命令未处理的源字段。
3. 超过`resultPartBytes`的结果另生成`parts/part-000001.txt`起的阅读分片，保留Unicode字符完整性；终端另返回分片目录及数量。完整文件供程序读取，分片供Agent按需读取。工具配置的`resultPartBytes`默认值为16384，限定每片字节上限，允许配置覆盖。
4. 所有错误详情、AJV问题、YAML诊断、HTTP响应、堆栈和服务日志写文件。参数错误提供参数名、有效值及修正命令；文件或服务错误提供错误位置及具体修正动作。
5. 文件保存本身失败时，入口在stderr输出简短的保存位置、系统错误码和修正动作，退出非零。入口不得输出待保存的大正文。
6. 维护执行者修改`source.ts`、`cli.ts`、`preview.ts`和`replay-fixture.ts`，移除各自直接输出完整结果的代码。Skill的`convert.mjs`统一调用`cli.ts`分派命令；入口加载失败也进入统一诊断处理。

### 4.3. 提供帮助和管道输入

1. 维护执行者在现有`tool-config.ts`集中定义命令说明、参数类型、默认值、必填性和典型示例。参数解析、帮助及错误示例使用同一份定义。
2. 根级`--help`提供命令及用途；`<命令> --help`提供该命令的参数、示例、结果文件入口和退出规则。帮助内容保存为文件，终端按第4.2节返回路径。
3. 任务参数为`-`时，入口从stdin读取上一个命令的短结果，打开其`resultFile`，获取其中的`taskFile`。打包结果还可提供`archive`给后续正式导入或预览。
4. 入口拒绝空stdin、无效JSON、失败结果及缺少所需字段的结果，并生成修正示例。显式参数与管道值冲突时报告冲突，由调用者选择一个输入。
5. 入口按参数类型解析路径，仅将路径参数转为调用者当前目录下的绝对路径，保留管道标记`-`。维护执行者移除`convert.mjs`对第一个参数直接执行路径解析的代码。
6. 以下为拟提供的调用方式；`$CLI`由调用者设置为Skill脚本路径，`$TASK`、`$ARCHIVE`均来自脚本结果：

   ```sh
   node "$CLI" --help
   node "$CLI" extract --help
   node "$CLI" begin "角色卡路径"
   node "$CLI" extract "$TASK" /data/description
   node "$CLI" pack "$TASK" | node "$CLI" formal -
   node "$CLI" preview "$TASK" --archive "$ARCHIVE"
   ```

### 4.4. begin与Agent的分工

#### 4.4.1. 输入、文件位置及返回接口

1. `begin <sourceFile>`接收用户指定的单个JSON或PNG角色卡。脚本解析一次源卡，在当前仓库的`.tmp/native-card-conversion/`下创建独立任务目录。目录名称由脚本生成；转换Agent沿用返回的路径。
2. 脚本将确定性结果写入任务目录的`package/`，将待判断内容写入`review/`。目标文件命名见第4.4.6节。
3. `begin`的命令结果`data`只提供`taskFile`、`packageDirectory`、`workFile`和`pendingCount`。`workFile`指向待处理事项索引；它的内容见第4.4.4节。终端输出按第4.2节返回结果文件路径。
4. 脚本不再向Agent提供`written`、已处理字段列表或逐字段转换记录。脚本保留只读源卡及后续命令需要的任务数据；这些程序内部文件不列为Agent的阅读材料。

#### 4.4.2. 确定性处理范围

1. 脚本按下表处理源字段。字符串直接映射时复制原文。

   | 源内容 | begin执行的处理 | 实际目标 |
   | --- | --- | --- |
   | `name`、`creator`、`character_version`、`tags`、`nickname`、`source` | 检查类型并按既有字段映射写入 | `character.json`对应字段 |
   | `description`、`personality`、`scenario`、`mes_example`、`system_prompt`、`post_history_instructions`、`creator_notes` | 按第4.4.3节筛选；符合直接映射条件时复制 | `character.json`对应字段 |
   | 世界书名称、`scan_depth`或`scanDepth`、`recursive_scanning`或`recursive`及目标同名扫描设置 | 转换已知字段名和类型；别名冲突交给Agent选择源值 | `worldbooks/book-0/book.json` |
   | 世界书条目的关键词、次关键词、启用状态、常驻、选择逻辑、插入顺序、位置、深度、消息角色、扫描和递归设置 | 复用`mapEntry`的字段转换及UID分配；符合第4.4.3节时连同原文写入 | `worldbooks/book-0/entries/e<源序号>.json` |
   | 正则的匹配表达式、替换文本、执行位置、启用状态、上下文范围、深度、编辑时执行及宏替换设置 | 复用`mapRegex`；符合第4.4.3节时原样保留表达式及替换文本 | `regex/source.json`中的对应规则 |
   | `fav`、`talkativeness`及既有映射配置列出的编辑器字段、无消费者字段、相同值别名 | 跳过写入；不同值别名交给Agent选择源值 | 无目标文件 |
   | 开场正文 | 将原文保存到待处理事项的内容文件；开场类型及初始化关系由Agent判断 | 第4.4.4节的待处理事项 |
   | 助手脚本、插件变量、未知扩展及目标无法直接承载的配置 | 保存需要判断的原文和字段 | 第4.4.4节的待处理事项 |

2. 世界书缺失的书级设置采用现有目标解析器的默认值；显式源值优先。维护执行者在`source-config.ts`集中声明源别名，在`write-config.ts`引用现有解析器的默认值。源卡提供但目标未消费的预算或插件设置进入待处理事项。
3. 世界书条目和正则规则使用同一处理顺序：begin对可直接转换的对象完成写入，对已知无用内容跳过写入，对待判断对象提供原文及源Pointer。待判断对象经Agent选择保留后，写入命令从只读源卡读取该对象并执行字段映射，具体写入规则见第4.4.5节。
4. 源书名称的缺省值也复用现有解析器；文件路径按第4.4.6节命名。源字段类型不合法或目标必填字段缺失时，脚本创建具体修正事项，不伪造源内容。

#### 4.4.3. 直接映射条件与待判断条件

1. 维护执行者在既有`source-config.ts`维护语法标记及字段规则。程序只检测字段、类型、标记、引用和配置值；内容的职责由Agent判断。
2. 人物正文和世界书条目满足以下全部条件时直接映射：字段类型合法；配置可由目标格式承载；标题、正文和关联扩展未命中MVU、变量输出协议、变量更新指令、EJS、插件调用、HTML、CSS、程序代码、状态展示或目标不支持的宏；其他源对象未以插件语法引用该内容。
3. 普通正则还须满足以下条件：匹配表达式、替换文本及规则名称未命中第2项标记；目标正则支持其全部执行条件。脚本保留规则在源数组中的顺序。
4. 命中标记的内容进入待处理事项；脚本提供命中的源位置和标记名称。`[initvar]`、`[mvu_update]`、`[mvu_plot]`及旧变量输出标签进入此分支，禁用状态不改变此分支。Agent按[Skill入口](../../../.agents/skills/native-card-conversion/SKILL.md)第2.3节决定具体目标。
5. 同一对象同时包含可直接映射的字段和待判断正文时，Agent只处理待判断正文或配置冲突。源对象中未知字段单独列为待判断字段；存在插件引用关系时，脚本把关联内容列为同一事项的阅读上下文。

#### 4.4.4. Agent读取和处理的内容

1. `workFile`仅包含begin尚未完成的事项，是begin结束时生成的只读索引；`pendingCount`表示该时点的事项数量。每项提供源Pointer、待处理原文的`contentFile`、需要Agent完成的具体动作，以及适用的关联原文路径或目标文件位置。具体动作包括选择冲突值、确定承载文件、删除旧协议、拆分混合职责及改写API代码。
2. 完整原文及长文本分片由`begin`在同一次调用中准备，采用第4.2节的字节上限。Agent先读事项索引，再读该事项的原文；涉及已写入目标字段时，索引提供必要的目标字段位置。
3. Agent不重新审阅全部已映射内容。`pendingCount`为0时，Agent直接进入索引、包校验和打包；不调用提取命令。
4. Agent作出决定后调用对应写入命令，完整文字通过源Pointer复制；需要拆分正文时，Agent将选定段落原样写入目标文件。HTML、CSS及程序代码按[Skill入口](../../../.agents/skills/native-card-conversion/SKILL.md)第3.3节转写。
5. 修正事项必须指出实际源位置、非法类型或冲突值，以及需要填写或选择的字段。不能从输入卡取得必要内容时，Agent停止并向用户报告缺失内容。

#### 4.4.5. 后续写入与原有结果合并

1. `map-entry`接收Agent选择保留的待判断条目的源Pointer，从只读源卡读取所选条目并映射配置；保留全文时使用既有`--copy-content`参数，拆分正文时按第4.4.4节第4项写入。脚本更新包内条目文件、`book.json.entryFiles`及`character.json.worldbooks`。
2. `map-regex`一次接收Agent对同一源正则数组中全部待判断规则的保留选择；脚本从只读源卡读取所选规则并映射配置，合并begin已保留的规则和本次选择，按源序号重建目标规则数组，并更新`character.json.regexProfiles`中的包内文件引用。删除或转写为其他模块的规则从目标正则数组移除。
3. 写入命令按源对象定位更新目标；重复提交同一选择替换同一文件或同一规则，不追加重复成员。Agent不重新提交begin已处理的全部字段或规则。
4. 写入及扫描顺序见第4.5节。

#### 4.4.6. 目标目录与文件的创建者

1. 各类目标文件按下表创建。

   | 目录或文件 | 创建者及命名依据 |
   | --- | --- |
   | `package/character.json` | begin按目标字段组装并写入；Agent通过写入工具补充待判断字段 |
   | `package/worldbooks/book-0/book.json` | begin创建源卡内嵌世界书；写入工具维护`entryFiles` |
   | `package/worldbooks/book-0/entries/e<源序号>.json` | begin写直接映射条目，map-entry写Agent保留的条目；文件名由脚本按源序号生成 |
   | `package/regex/source.json` | begin及map-regex共同维护；源规则的序号决定数组顺序 |
   | `package/openings.json`及`package/openings/<开场ID>.txt` | Agent决定开场类型及文本范围后，由既有写入工具创建 |
   | `package/state/`、`package/agents/`、`package/frontend/`、`package/backend/`、`package/data/`、`package/assets/` | Agent按待判断内容的职责及[目标文件与格式](../../../.agents/skills/native-card-conversion/references/conversion-map.md)第1、2章创建 |
   | `package/manifest.json` | index根据实际目标文件创建 |

2. begin按目标格式的必填字段决定人物文件是否能够完成；缺少必填字段时按第4.4.4节第5项处理。文件创建不再以`written.length`为条件。世界书和正则的创建由实际存在的源对象及已保留内容决定。
3. begin及后续写入命令使用同一源序号和UID分配函数，从同一只读源卡取得稳定标识；删除条目不会重新编号其他条目。

#### 4.4.7. 关联内容提取

1. 维护执行者将`read`改名为`extract`。`extract <taskFile> <pointer>...`用于读取begin未提供的关联字段；Agent传入所需Pointer，脚本一次解析源卡并返回各字段的内容文件路径。
2. 每次提取使用独立调用目录。不同调用、不同Pointer及分片文件互不覆盖；内容保存与begin共用函数。
3. 无效Pointer生成该项诊断，整体退出非零；已成功提取的文件保留。诊断给出需修正的Pointer及正确调用示例。

### 4.5. 按文件安排写入和扫描

1. 一个转换Agent负责本次角色包。Agent按目标文件分配写入操作，不同文件可以并发写入；同一文件的字段修改合并到一次调用，后续修改在前一次调用结束后执行。
2. 维护执行者修改`copy`和`parse`，增加可重复的`--field <sourcePointer> <targetPointer>`参数，对一个目标JSON提交多项字段修改。批量调用使用`copy <taskFile> <targetFile> --field ...`或`parse <taskFile> <targetFile> --format json|yaml --field ...`。脚本一次读取源卡和目标文件，计算全部字段值，再一次写回目标。任一项解析或结构检查失败时，目标文件保持原样。
3. 同一次调用出现重复或父子重叠的目标Pointer时，脚本返回冲突位置，要求调用者合并修改或分别顺序调用。单次字段调用和整文件替换继续使用已有参数。
4. `map-entry`批量处理一次解析源卡、计算一次UID映射，再写入选中的独立条目文件。脚本在写入每个目标对象前完成该对象的结构检查；失败对象保持原文件。批量结果逐项记录目标文件路径、写入状态和失败诊断。
5. `map-regex`按第4.4.5节第2项接收待判断规则的选择，检查合并后的整个目标数组，再替换文件。
6. 维护执行者修改`atomic-write.ts`，将临时文件写入当前调用目录，在相同文件系统内rename到包目录。包目录中只出现最终角色包文件。
7. Agent等待全部包写入完成后，依次调用`index`、`validate`和`pack`；这些命令执行期间，Agent不修改该包。维护执行者将此顺序写入Skill流程。
8. 本方案不支持多个进程同时修改同一目标文件，也不支持修改包时扫描或打包。程序保留单文件原子替换，不新增任务锁、等待队列、PID记录或解锁命令。

### 4.6. 绑定独立ZIP

1. 维护执行者修改`tool.ts`的`pack`，在包写入完成后读取一份文件集合，使用同一份内容进行校验和打包，再校验实际ZIP。打包记录指向本次实际ZIP的校验结果。
2. `pack`保留独立归档路径，停止发布可被覆盖的任务级`role.zip`及其旧版副本。结果文件中的`archive`作为交付ZIP路径。
3. `formal`和`preview`接受必填的`--archive`，也可由第4.3节的打包管道取得该值。维护执行者修改CLI和`preview.ts`，取消读取固定ZIP的路径。

### 4.7. 服务隔离和创建重试

1. 维护执行者修改`formal.ts`的父目录创建：父目录已由其他进程创建时，核对该路径确为目录，再创建本次独立子目录；其他创建错误进入诊断文件。
2. 独立`replay-fixture`把用户指定目录作为父目录，每个实例创建自己的子目录，分别保存请求日志和summary。维护执行者在监听后的初始化代码外围加入清理：初始化失败先关闭监听，再返回错误。
3. `preview`保留现有独立运行目录、端口及环境变量清理。预览和回放的启动结果写入当前调用目录的`ready/result.json`，关闭结果写入`closed/result.json`；终端分别返回对应路径，错误按第4.2节处理。预览和回放继续作为前台进程运行。
4. `begin`、`formal`、`preview`和独立回放增加可选`--request-id <UUID>`。调用者需要可重试的创建时，在第一次调用前生成一次ID并在重试时沿用；未提供时脚本生成新ID。
5. 同一ID对应固定的创建目录。`begin`在同一ID已有完整任务时返回该任务；调用者需要重新读取已变更的源文件时，使用新ID。
6. 脚本在创建目录中保存该次调用的输入路径和参数；相同ID携带不同输入路径或参数时报告冲突。`formal`在同一ID已有完整成功结果时返回该结果；导入尚在执行时等待已有进程结果。前台服务在同一ID已有活动进程时返回其已有启动结果；仍在启动时等待该结果。工具配置的`creationWaitMs`默认值为60000，限定等待毫秒数；达到上限后报告进程和目录位置，重试不得再创建一个服务或执行第二次导入。
7. 相同ID留下未完成任务、失败导入或已关闭服务时，命令返回对应状态及诊断，保留已产生的文件。调用者修正问题后使用新ID重新创建；程序不重放中断前的请求。
