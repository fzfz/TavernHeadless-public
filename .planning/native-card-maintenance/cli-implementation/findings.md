# 实施发现

## 1. 开始时的实现

1. Skill入口分别分派source、write、index和cli。
2. 实施开始时begin只写人物字段；世界书、正则和开场全部进入pending。
3. 实施开始时，预览读取固定role.zip，独立回放直接使用指定目录。

## 2. 数据流与服务缺陷

1. 旧命令直接输出完整JSON，宿主会截断大文本。公共输出模块现保存完整结果及长内容分片，终端仅返回文件路径。

2. Vite默认启动日志污染stdout。preview.ts改为将Vite日志写入独立证据目录；终端只输出结果文件路径。
3. Vite默认SIGTERM处理会调用process.exit，抢先结束CLI关闭流程。preview.ts使用中间件模式及自管HTTP监听，CLI负责关闭所有服务及写入关闭结果。
4. 同ID服务重试可能返回已结束服务的旧地址。creation.ts在复用服务结果前访问本机地址；访问失败时返回诊断，要求检查原服务或使用新ID。
5. 参数选项位于位置参数之前时，旧分派顺序会改变后续命令输入。cli.ts分别收集位置参数和选项，再按命令接口顺序分派。

## 3. 字段映射缺陷

1. begin原实现缺少[实施方案第4.4.3节](../cli-audit/implementation-plan.md#443-直接映射条件与待判断条件)的语法标记检测；含EJS的人物正文、禁用的initvar条目和HTML正则会直接写入目标。源队员已补充集中标记及对应待判断项。
2. begin将独立资源写入放在人物schema成功分支内；姓名错误时已映射资源没有落盘。源队员已解除该条件。
3. 后续正则写入重算ID但未使用碰撞避让，且保留所有旧规则。write队员已统一ID分配，只合并自动结果与本次选择。

## 4. 最终复核修复

1. 关联Pointer没有对应原文文件，Agent仍需额外提取。begin现同次写入contexts中的原文文件和长文本分片。
2. 帮助承诺的单边片段默认值未实现。copy和parse现共用起点0、终点源长度的规则；旧拒绝用例已改为有效默认值测试。
3. 世界书文件名拼接在多个位置重复。source-config现提供共同的命名、路径及序号函数；character路径从正式文件规则取得。
4. map-entry会更新共享book和character。工具文档现明确逐次完成该命令，同一书多个条目用indices批量提交。
5. 全量测试复现预览关闭后Vite仍写deps_temp缓存，递归清理报ENOTEMPTY。preview现等待请求空闲、依赖扫描及优化写入结束后关闭；最终全量测试清理成功。
6. 全量静态检查误读历史维护脚本。ESLint和Vitest统一排除.planning；ESLint和Vitest根据runtime.outputDirectory排除运行产物目录。

7. map-entry执行器曾要求indices先于copy-content，公共解析却允许反序。CLI现按共享参数定义排列选项，反序输入和完整命令链39项通过。
