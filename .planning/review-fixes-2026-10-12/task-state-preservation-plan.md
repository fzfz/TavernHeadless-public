# 页面宏绑定任务状态保留修复计划

## 1. 名词定义

1. 输入任务、派生任务、持久状态记录：采用[状态写入并发修复计划第1章](concurrent-state-plan.md#1-名词定义)的定义。
2. 页面宏绑定：`bind-page-macros` 命令按转换 Agent 提交的源区间和用途选择，生成前端文字绑定。

## 2. 总目标

1. 页面宏绑定生成派生任务时完整保留持久状态记录，使后续状态命令读取已提交的权限和源字段覆盖结果。

## 3. 修复前实现调研

1. `page-macro-bindings.ts` 的 `bindPageMacros()` 校验绑定请求与前端产物后，复制角色交付包及源快照，创建任务文件。
2. `state-write.ts` 的 `submit()` 从任务目录读取权限、源字段清单和覆盖记录，并由权限记录生成 `writablePaths`。
3. 修复前宏绑定具有独立目录及失败清理行为，但任务派生代码仅覆盖包与源快照。

## 4. 面临的问题与根因

1. `.tmp/review-four-plans-2026-10-12/spec-probe-four.jsonl` 记录宏绑定前 `/count` 可写，绑定后执行 state-paths 时可写路径变为空。
2. 宏绑定遗漏三份持久状态记录，后续 state-paths 读取权限记录得到空权限，并据此改写变量更新配置。
3. 对照采用同一份权限输入，经过任务派生后权限记录消失；state-paths 在输入任务仍能保留 `/count`，因此根因不在权限推导算法，而在宏绑定遗漏任务持久输入。
4. 任务派生代码没有覆盖任务的全部持久输入，角色交付包中的配置与任务目录中的权限来源因而脱节。本次补全共享任务派生职责，使宏绑定与状态写入采用相同持久输入。

## 5. 问题的解决和实施方案

### 5.1. 实施架构

1. 页面宏绑定复用[状态写入并发修复计划第5章](concurrent-state-plan.md#5-问题的解决和实施方案)的共享任务派生器。

```mermaid
flowchart LR
  A[含已提交状态的输入任务] --> B[共享任务派生器]
  B --> C[完整派生任务]
  C --> D[页面宏绑定文件写入]
  D --> E[返回任务路径]
  E --> F[后续状态命令读取持久状态记录]
```

### 5.2. 实施步骤

1. 执行者先建立 state-source、state-schema、bind-page-macros、state-paths 的回归链，验证宏绑定后的实际权限与源字段覆盖行为。
2. 执行者将 `bindPageMacros()` 的目录创建与复制代码替换为共享任务派生器调用，保留宏生成及前端校验职责；派生器直接消费 `state-write-config.json` 中的文件名配置。
3. 执行者核对派生任务中的三份持久状态记录与输入记录内容相同，并验证后续状态命令继续使用它们。
4. 执行者运行现有二进制资源保留、连续宏绑定、并发绑定及失败清理回归。

## 6. 方案待决策项清单

1. 当前待决策项为空。

## 7. 计划验收清单

1. 宏绑定返回任务中的三份持久状态记录完整保留，输入任务与二进制资源保持原内容。
2. 宏绑定后的 state-paths 保留此前选择的 `/count` 可写权限；后续 state-schema 读取保留的源字段覆盖记录并核对源字段对应。
3. 连续状态写入与宏绑定均沿返回任务执行，最终 ZIP 通过角色交付包检查；`verifyFormalPackage()` 调用 `POST /native-cards/imports` 和 `POST /native-cards/imports/:id/confirm`，核对检查响应和导入成功响应。
4. 定向测试覆盖宏绑定并发成功、失败清理及连续绑定。

## 8. 非本次目标

1. 扩展页面宏支持范围。
2. 调整绑定请求格式。
3. 改变生成模块的运行行为。
