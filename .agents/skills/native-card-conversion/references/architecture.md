# 源角色卡架构与原生角色卡架构

1. 适用版本与实现证据见[版本及来源](sources.md)；目标文件和格式见[原生格式对照](conversion-map.md#2-内容对应的文件与读取入口)。

## 1. 源架构：SillyTavern 角色卡

1. SillyTavern 角色卡保存人物资料、开场和扩展配置。预设决定提示如何组装，世界书提供条件激活的内容，正则处理文本，助手脚本和 MVU 等插件提供额外运行能力。角色卡中的一个字段可以同时携带几种组件的内容。

### 1.1 正则是什么

1. 正则规则根据匹配式找到文本，再用替换内容处理它。规则的启用状态、作用范围、消息深度和编辑条件决定何时执行；正文显示和发给模型的提示文本可以使用不同处理。

2. 有些规则执行文本删除或替换；有些规则用替换内容插入 HTML 状态栏，HTML 中又含变量读取和按钮脚本。这时，匹配式是挂载入口，HTML 是展示内容，脚本负责读取数据或执行操作。转换 Agent 分别识别这些职责。字段及作用范围见[正则字段](extension-fields.md#1-正则字段)。

### 1.2 世界书是什么

1. 世界书是一组可供提示组装器或插件读取的条目。角色卡可以内嵌世界书，也可以绑定外部世界书。扫描器根据关键词、常驻设置及其他条件激活条目，再按位置、顺序、深度和消息角色注入提示。

2. 条目正文保存什么与扫描器怎样激活它是两件事。正文可以保存人物事实、剧情规则，也可以保存插件读取的初始化数据、变量变化规则或模板。插件按标题、ID 等条件显式读取条目时，读取关系由插件决定；条目的扫描启用状态只控制扫描入口。转换 Agent 阅读正文及其读取者，再决定各部分的职责。字段及关联资料见[世界书参考](worldbook-fields.md)。

### 1.3 MVU 框架是什么

1. MVU 为角色卡管理变量初始化、更新操作和相关事件。使用正文更新协议的卡要求正文模型输出变量操作，MVU 解析这些操作并更新变量；状态栏脚本读取变量来显示结果。变量初值、变化规则、类型约束、计算脚本与显示模板分别承担不同职责。

2. MVU 世界书标题含 `[initvar]` 的条目提供初值；禁用提示扫描不阻止 MVU 读取它。初始化顺序与版本证据见[MVU 初始化消费](extension-fields.md#3-mvu-初始化消费)。

3. 世界书标题中的 `[mvu_plot]` 和 `[mvu_update]` 是模型阶段的路由标记。在分步更新模式中，仅含 `[mvu_plot]` 的条目供剧情模型读取，仅含 `[mvu_update]` 的条目供更新模型读取；无标记或同时含两种标记的条目可供两个阶段读取。随正文一起更新时，这两种标记不划分模型阶段。条目仍按世界书的激活条件与适用的筛选配置参与请求。

4. 标记说明源读取阶段，条目正文决定具体用途。转换时按[MVU 条目归属](semantic-experience.md#3-世界书读取与动态提示)分别处理叙事、变量规则及混合内容。源路由依据为 [MVU 条目阶段筛选](https://github.com/MagicalAstrogy/MagVarUpdate/blob/b13b43bac24d585f2b523c12e423bb803fa9dd7c/src/function/request/filter_entries.ts)。

### 1.4 助手脚本是什么

1. 助手脚本在源环境中连接变量、消息、页面、按钮和酒馆事件。它可以读取世界书、生成动态提示、执行公式或组织交互。浏览器存储、iframe、全局 DOM 和插件事件都属于其源运行环境。

2. 这些 API 调用由浏览器脚本发起，参数和执行时机来自脚本及页面事件。源插件若另行注册模型工具，则由模型请求调用，插件执行后返回结果；这种注册与运行关系需要从实际插件代码确认。

3. 同一个脚本可以兼有界面操作和剧情状态操作。转换 Agent 通过它读取的数据、调用对象、写入结果及事件关系判断职责。具体字段见[助手与扩展参考](extension-fields.md#2-助手与其他扩展)。

### 1.5 人物、开场与预设怎样参与运行

1. 人物资料、系统提示、历史后指令和对话示例由预设及全局设置参与组装。字段存在于卡中，只说明卡保存了它；实际模型请求由当前组装流程决定。

2. 开场正文建立已经发生的剧情事实。开场也可以嵌入初始化块或页面入口，这些内容分别由插件或显示处理读取。人物字段、宏与开场类型见[角色字段参考](character-fields.md)。

## 2. 目标架构：TavernHeadless 原生角色卡

1. 原生角色包分别保存人物、开场、世界书、状态规则、后端模块、前端和资源。完整目录树、固定与可选文件名、Agent 与脚本的创建责任见[原生包目录](conversion-map.md#1-包目录与命名)。

### 2.1 人物、开场与提示组装

1. 人物组件提供人物事实和叙事要求，开场提供起始剧情及对应初始状态。预设规定提示节点和组装顺序，世界书提供被激活的内容，提示控制器根据状态生成动态提示。

2. 正文模型接收实际组装后的资料与历史，生成剧情正文。源世界书或模板中的描写要求由这些提示组件承接；变量保存指令按第2.2节交给状态执行者。提示字段与扫描来源见[角色字段](character-fields.md#2-人物提示与开场)及[世界书扫描来源](worldbook-fields.md#3-扫描来源递归与预算)。

### 2.2 初始状态与独立状态 Agent

1. 各开场具有由源初始化逻辑推导出的初始状态。剧情正文保存后，独立状态 Agent 根据当前变量、实际来源消息和本卡更新规则提出变量变化。

2. 状态 Agent 使用单独的状态预设。绑定与读取规则见[状态提示词组装](api/state-prompt-assembly.md)。
3. 正式状态请求复用提示组装器，并按状态预设、历史、来源消息与状态数据生成模型消息。规则内容的目标归属见[语义判定经验第3章](semantic-experience.md#3-世界书读取与动态提示)；状态规则文件和控制器配置边界见[目标文件与格式第2章](conversion-map.md#2-内容对应的文件与读取入口)。
4. 状态请求的 dry-run 路由、响应字段及组装追踪见[状态提示词组装](api/state-prompt-assembly.md)。

### 2.3 后端计算、校验与正式保存

1. 后端检查提议的写入权限、派生路径和冲突，应用提议，运行确定性计算，再进行状态结构与业务校验。通过检查的结果保存为正式状态快照。

2. 计算模块负责公式结果；校验模块负责业务守卫。转换 Agent 为每项变化指定一个实际写入者，并按该职责确定变量归属。模块契约见[后端 API](api/backend-api.md)。

### 2.4 原生世界书与提示控制器

1. 原生世界书承担关键词、注入位置及其他已有静态触发规则。提示控制器读取原生状态，处理适用的动态条件和提示内容。世界书中的人物事实、状态更新指令、初始化数据和前端模板按各自职责进入对应组件。

2. 仅保存插件配置不会产生源插件的运行效果。转换 Agent 根据源功能检查世界书、控制器、状态规则和正式工具是否能够承接其实际结果。具体支持字段和边界见[世界书字段参考](worldbook-fields.md)。

### 2.5 原生前端与状态读取

1. 原生角色 HTML 和 CSS 挂载在同页面的 ShadowRoot 中，前端模块通过正式 API 读取状态、消息和资源，处理界面事件及生命周期。源 iframe、全局 DOM 或浏览器存储的职责需要按原生作用域分别承接。

2. 前端局部状态保存展开、滚动和弹窗等界面行为。剧情变量和持久解锁结果由正式状态或资源保存。历史查看显示所选快照；影响当前剧情的动作按最新状态判断，两种状态分别使用。页面入口、变量和历史 API 见[前端 API](api/script-api.md)及[模板契约](api/script-template-api.md)。

### 2.6 正文模型的工具调用

1. 转换 Agent 按[消费者与执行时点](semantic-experience.md#4-计算与工具调用)判断是否需要正文模型主动取得结果。系统预置 `random` 负责随机采样，`calculate` 负责明确数值的受限计算。角色资料提供调用条件、参数取值规则和结果用途；发布或试聊配置提供调用授权。包外配置及参数契约见[正文模型系统能力](api/model-capabilities.md)。

2. 正文模型在生成中提出调用，系统执行并把结果回传到同轮下一次模型请求。正文模型读取工具结果后，确定依赖该结果的参数或继续生成剧情。后端保存本轮成功完成的正文。

3. 状态 Agent 和后端模块取得与最终正文关联的只读 `toolEvidence`。执行结果证明采样或计算完成，状态 Agent 结合已保存正文判断行动是否发生；状态重算使用原执行结果。结果结构、执行归属和提案引用见[同轮结果和状态证据](api/model-capabilities.md#同轮结果和状态证据)。
