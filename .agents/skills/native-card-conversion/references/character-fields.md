# 角色卡字段的用途与处理

1. 目标文件及读取这些文件的模块见[目标文件与格式第1、2章](conversion-map.md)。

## 1. 格式与字段判断

1. 适用格式和实现版本见[适用版本与来源](sources.md#1-适用版本与正式来源)。CCv1 的人物字段位于顶层；CCv2、CCv3 的人物字段位于 `data`。转换 Agent 按源封装读取对应人物字段。

   | 源字段                 | 源用途             | 原生处理依据                                     |
   | ---------------------- | ------------------ | ------------------------------------------------ |
   | `spec`、`spec_version` | 交换格式及版本标识 | 用于解释源数据；ZIP 使用原生 manifest 的格式标识 |

## 2. 人物、提示与开场

1. | 源字段                           | 源用途                               | 原生处理依据                                                                                                                           |
   | -------------------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
   | `name`                           | 角色名称和相关宏的身份来源           | 写入人物名称；检查其他称谓、宏和台词的实际主体                                                                                         |
   | `description`                    | 人物描述，可能混入指令或页面片段     | 人物事实进入人物资料；混合内容按实际职责拆分                                                                                           |
   | `personality`                    | 性格与表达方式资料                   | 转换 Agent 保留性格与表达方式约束，并检查所选预设组装的实际请求是否包含这些约束                                                        |
   | `scenario`                       | 场景、背景及初始关系                 | 保存有效背景；开场特有的状态和正文按[目标文件与格式第2章](conversion-map.md#2-内容对应的文件与读取入口)分别保存                        |
   | `mes_example`                    | 对话、文风和说话者示例               | 转换 Agent 将对话示例写入原生 `exampleDialogue` 或本次转换采用的提示资源，并核对示例分隔与人物宏                                       |
   | `system_prompt`                  | 角色级系统提示，效果受源预设设置影响 | 分开叙事要求与变量更新要求；人物提示进入 `systemPrompt` 后核对所选预设组装的实际请求内容及注入位置                                     |
   | `post_history_instructions`      | 历史后指令，效果受源设置影响         | 使用 `postHistoryInstructions` 时验收实际请求位置                                                                                      |
   | `first_mes`                      | 默认开场正文                         | 转换 Agent 建立默认开场，并按[目标文件与格式第2章](conversion-map.md#2-内容对应的文件与读取入口)分别保存开场正文、初始化状态和页面内容 |
   | `alternate_greetings`            | 其他候选开场，也参与源群聊开场候选   | 逐项阅读正文与初始状态；保存适用对象和开场选择关系                                                                                     |
   | `group_only_greetings`           | CCv3 群聊专用开场                    | 标明 `audience: group`；按本次目标会话核对有效内容                                                                                     |
   | `character_book`                 | 内嵌世界书                           | 按[世界书字段参考](worldbook-fields.md)处理条目和书级设置                                                                              |
   | `extensions.depth_prompt.prompt` | 固定深度注入的文本                   | 转换 Agent 按[目标文件与格式第2章](conversion-map.md#2-内容对应的文件与读取入口)选择世界书条目或提示控制器，保存深度提示正文           |
   | `extensions.depth_prompt.depth`  | 从历史末端计数的注入深度             | 核对目标注入位置、边界和历史不足时的行为                                                                                               |
   | `extensions.depth_prompt.role`   | 深度提示的消息角色                   | 按目标角色枚举转换并核对实际请求                                                                                                       |

2. 转换 Agent 保留目标正式支持的提示宏。源插件宏用于提示时，转换 Agent 将其取值和条件逻辑转写到提示控制器；页面宏按[页面宏绑定](tools.md#bind-page-macros生成页面宏绑定)处理；初值字符串按[文字和状态内容第3.2节](../SKILL.md#32-写入文字和状态内容)处理。人物别名参与宏取值时，转换 Agent 保留源别名与显示名称的区别。所需宏行为无法转写时，转换 Agent 按[入口第5.2节](../SKILL.md#52-能力缺口)处理。初始化标签按[MVU 初始化消费](extension-fields.md#3-mvu-初始化消费)处理。

3. 转换 Agent 核对原生预设图缺少相应人物节点时补入的系统提示和历史后指令节点，并确认已有节点的启用状态和位置对组装的影响。转换 Agent 按[核心验收第2.2节](acceptance.md#22-实际请求检查)检查提示内容和顺序。

## 3. 元数据与资源

1. | 源字段                                      | 源用途                                             | 原生处理依据                                                                                             |
   | ------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
   | `creator_notes`、`creatorcomment`           | 作者说明及使用指引                                 | 转换 Agent 按[目标文件与格式第2章](conversion-map.md#2-内容对应的文件与读取入口)确定待判断内容的目标文件 |
   | `creator_notes_multilingual`                | CCv3 按语言代码保存的作者说明                      | 转换 Agent 选择目标读者使用的源语言条目，保留语言标识与正文，目标位置按[目标文件与格式第2章](conversion-map.md#2-内容对应的文件与读取入口)确定                                                         |
   | `creator`                                   | 作者信息                                           | 保存为原生 `creator` 或来源记录                                                                          |
   | `character_version`                         | 作者定义的卡版本                                   | 保存为 `characterVersion`，与目标包格式版本分别记录                                                      |
   | `tags`                                      | 分类、检索及部分功能的筛选条件                     | 保存有效标签；存在筛选引用时核对相关条件                                                                 |
   | `nickname`                                  | CCv3 为人物宏提供的别名                            | 保存别名并检查实际宏消费；显示名称和剧情称谓分别核对                                                     |
   | `source`                                    | CCv3 的来源 ID 或 URL 数组，也可能出现平台自定义值 | 原生人物 `source` 是字符串；按实际用途改写或保存结构化来源资源                                           |
   | `creation_date`、`modification_date`        | CCv3 以秒为单位的 Unix 时间戳                      | 转换 Agent 将源秒级时间戳转换为 ISO 8601 字符串，分别写入原生 `createdAt`、`updatedAt`；源字段缺失时省略对应目标字段                               |
   | `avatar`                                    | 平台头像指针或源图像标识                           | 确认是否指向可取得的资源，按目标资源契约使用                                                             |
   | `assets`                                    | CCv3 的资源数组                                    | 分别分析图标、背景、表情、音频及其他资源的用途                                                           |
   | `assets[].type`                             | 资源类别                                           | 选择目标资源或前端呈现职责                                                                               |
   | `assets[].uri`                              | 资源地址或嵌入资源引用                             | 核对可访问性、内容及已有取得授权，生成目标资源引用                                                       |
   | `assets[].name`                             | 资源名称或主资源标识                               | 保留其选择、关联和呈现用途                                                                               |
   | `assets[].ext`                              | 资源扩展名                                         | 核对实际类型及目标允许格式                                                                               |
   | `fav`、`extensions.fav`                     | 酒馆收藏标记                                       | `begin` 从转换结果中排除这些字段                                                                         |
   | `talkativeness`、`extensions.talkativeness` | 酒馆群聊角色选择权重                               | `begin` 从转换结果中排除这些字段                                                                         |
   | `extensions.world`                          | 外部世界书绑定名称                                 | 按[世界书读取规则](worldbook-fields.md#1-书级设置与内容职责)解析引用                                     |

2. 资源存在于输入中与资源成功加载分别验收。Agent 核对实际使用的图像、字体、音频、网址和嵌入内容；未使用的来源资料可以退出运行包，记录其原用途和删除理由。

3. 需要保留媒体时，按卡中的资源内容或地址及目标资源契约生成资源文件与引用。内容缺失时按[入口第2.4节](../SKILL.md#24-判断外部引用缺失的影响)处理；需要取得外部资源时按[执行条件](../SKILL.md#5-排除项能力缺口与执行条件)核对授权。

## 4. 脚本与平台扩展

1. `extensions.regex_scripts` 按[正则与助手字段](extension-fields.md#1-正则字段)分析。`extensions.tavern_helper` 按[助手字段](extension-fields.md#2-助手与其他扩展)分析，读取其实际值及字段结构。

2. 其他平台或插件字段按[助手与其他扩展](extension-fields.md#2-助手与其他扩展)分析。
