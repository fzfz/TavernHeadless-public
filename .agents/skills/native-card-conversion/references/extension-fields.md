# 正则、助手与插件字段

1. 转换 Agent 确认用途后，按[目标文件与格式第1、2章](conversion-map.md)选择原生文件。

## 1. 正则字段

1. 适用版本见[适用版本与来源](sources.md#1-适用版本与正式来源)。SillyTavern 正则在启用状态、上下文类型、编辑条件、深度和 placement 都满足时运行。Agent 阅读每个脚本的匹配对象、替换内容及实际执行范围，再按[原生架构](architecture.md#2-目标架构tavernheadless-原生角色卡)选择目标职责。

   | 源字段                 | 源用途                                | 转换时的判断                                                                                                         |
   | ---------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
   | `id`                   | 脚本身份                              | 保留来源定位，重建引用时同步关联                                                                                     |
   | `scriptName`           | 名称与编辑器显示                      | 用于定位与资料；实际功能由内容决定                                                                                   |
   | `findRegex`            | 匹配表达式及标志                      | 推导实际输入、捕获组和边界                                                                                           |
   | `replaceString`        | 替换文本，可含捕获组、宏、HTML 和脚本 | 将文本变换、布局、事件及状态逻辑分别处理                                                                             |
   | `trimStrings`          | 从匹配结果中清理指定内容              | 判断清理对象及其保留的有效语义                                                                                       |
   | `placement`            | 运行对象数组                          | `1` 用户输入、`2` AI 输出、`3` slash command、`5` 世界书、`6` 推理；`0` 为已弃用 Markdown 显示值，`4` 为旧 sendAs 值 |
   | `disabled`             | 禁用脚本                              | 按启用状态及本次必要性保留资料或删除                                                                                 |
   | `markdownOnly`         | 限定显示处理范围                      | 判断有效视觉功能和实际提示影响                                                                                       |
   | `promptOnly`           | 限定提示处理范围                      | 判断请求文本的实际变化                                                                                               |
   | `runOnEdit`            | 编辑消息时运行                        | 保留需要的编辑后结果及触发条件                                                                                       |
   | `minDepth`、`maxDepth` | 对应历史深度的运行限制                | 核对楼层、历史边界及空值语义                                                                                         |
   | `substituteRegex`      | 查找表达式中的宏替换模式              | `0` 不替换、`1` 原样替换、`2` 转义后替换；源布尔值 `false` 转为 `0`，`true` 转为 `1`；按实际宏值验收                 |

2. 正则中的页面、状态操作和文本变换按[语义归属](semantic-experience.md#2-正则页面与显示)分别承接。旧挂载式、状态栏隐藏、变量更新块裁剪和格式清理按[删除与改写的判断](semantic-experience.md#6-删除与改写的判断)处理。

3. 需要目标文本正则时，Agent 核对目标 regex profile schema 支持的作用域、顺序、表达式和替换语法，再保存与验收。

   `map-regex` 原样复制本节列出的固定字段，按表中的规则转换 `substituteRegex`；缺少 `trimStrings` 时写入空数组，缺少 `substituteRegex` 时写入 `0`。缺少可选深度字段时保持未写入。ID 分配按[转换工具第1章的 map-regex](tools.md#map-regex写入已选择保留的正则)处理；其他必填字段缺失或字段类型不符合目标格式时，脚本返回对应源位置的问题。未列出的字段由转换 Agent 判断用途。

4. 源依据为[正则运行引擎](https://github.com/SillyTavern/SillyTavern/blob/51ad27fb86d39a3daca3adaa970375c9670c12df/public/scripts/extensions/regex/engine.js)中的 placement、替换与运行筛选，以及[正则编辑器](https://github.com/SillyTavern/SillyTavern/blob/51ad27fb86d39a3daca3adaa970375c9670c12df/public/scripts/extensions/regex/index.js)中的保存字段。

## 2. 助手与其他扩展

1. `tavern_helper` 可以是对象，也可以按键值对数组保存。Agent 从本次实际成员取得脚本、脚本库、按钮及配置。脚本成员可能使用 `name`、`id`、`enabled`、`content`、`type`、`buttons`、`data` 或其他插件自定义字段；字段意义由对应插件和脚本读取位置确定。

   | 内容                        | 原用途                        | 原生处理依据                                                   |
   | --------------------------- | ----------------------------- | -------------------------------------------------------------- |
   | 脚本正文和导入              | 提供变量、事件、UI 或生成行为 | 阅读参数、绑定、返回值、副作用、异步顺序及实际引用，按职责重写 |
   | 启用标记与脚本类别          | 决定启动或引用关系            | 判断有效入口与依赖；模块生命周期使用正式契约                   |
   | 按钮名称与行为              | 提供用户操作和反馈            | 前端布局与事件处理模块                                         |
   | 按钮可见条件                | 按变量或运行状态显示操作      | 使用正式变量与发送锁状态，测试条件变化                         |
   | `data` 和其他配置成员       | 脚本参数、资源或持久状态      | 可调整配置写入数据文件；持久剧情状态按正式变量职责处理         |
   | 浏览器存储读写              | 缓存、界面偏好或跨轮状态      | 按实际持久性和作用对象选择正式状态或界面状态                   |
   | 全局 DOM、iframe 与酒馆事件 | 连接源页面及插件生命周期      | 使用正式页面入口、事件和释放契约重写                           |
   | MVU 初始化、更新和修复      | 建立变量并处理更新失败        | 使用原生 Agent、计算、校验与正式修复接口保留有效操作           |
   | 直接生成与供应商参数        | 请求辅助内容或执行另一种生成  | 根据功能目的检查正式 Agent tools 和模型调用契约，核对已有授权  |

2. 源加载器、解析器和正文协议按[删除与改写的判断](semantic-experience.md#6-删除与改写的判断)处理。外部模块、资源或插件消费资料缺失时，按[入口第2.4节的缺失内容处理](../SKILL.md#24-记录转换决定与缺失内容)处理。

3. 对于其他自定义字段，转换 Agent 根据实际消费者解释检索、模型参数、页面模板、来源标识或任务行为，记录取值影响和目标处理结果。

## 3. MVU 初始化消费

1. 输入启用 MVU 时，Agent 阅读其实际初始化入口，区分世界书的提示扫描状态与变量初始化消费。下述消费依据为 [MagVarUpdate 初始化实现](https://github.com/MagicalAstrogy/MagVarUpdate/blob/b13b43bac24d585f2b523c12e423bb803fa9dd7c/src/function/initvar/variable_init.ts)；源卡绑定其他版本时按相应实现核对。

2. `loadInitVarData` 从已绑定世界书读取条目，按条目 `comment` 中的 `[initvar]` 标记选取初值，条目的提示扫描启用标记独立于这个入口。Agent 根据该入口判断初值用途，并把实际初值保存到原生开场的初始状态文件。

3. Agent 先定位初始化内容所在的消息来源、楼层、执行入口及触发条件，再按源入口推导状态。所引版本的 `initCheck` 在最后消息索引为 `0`、即聊天当前只有首条消息时扫描第一条助手开场的各个 swipe（同一消息的候选文本）；其中有效 `<initvar>` 的内容替代主角色世界书初值，随后重新处理适用的其他世界书初始化，再触发初始化回调。前端通过 `/send` 新增的用户消息按后续消息入口处理；Agent 根据实际命令解析和回调判断其中各块是否产生状态操作。

4. 开场中的 `<update>` 字面量 `_.set` 或适用版本的 JSONPatch 按实际解析出的操作顺序覆写指定字段，其余已有字段继续保留。Agent 结合消息入口、初始化回调和源 schema 的运算顺序取得各开场的实际初始状态。Zod 默认值按字段缺失条件参与处理；已提供的值按源 schema 校验与变换。

5. 原生系统按[状态更新流程](architecture.md#22-初始状态与独立状态-agent)保存初值和后续状态。初始化消费依据、启用入口、来源字段及开场差异写入本次字段决策与行为映射。
