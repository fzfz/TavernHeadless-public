# 本地角色卡第 2 组研究

## 范围与证据

本组读取 38 张本地角色卡的路径与 mtime 匹配缓存。唯一原始来源为 `/srv/data/mac bookpro old/AI/SillyTavern`。逐卡原 PNG、缓存和副本的绝对路径保存在 [结构化结果](batch-2-results.json) 的 `cards` 数组，卡 ID 与下表一致。缓存中的 `chara_card_v3` 只说明缓存结构，不能证明原 PNG 的制作格式。本文的 JSON pointer 均从缓存根对象开始。

本研究读取开场、世界书结构、正则配置及相关可见脚本源码，没有执行卡脚本、访问网络、读取聊天记录或凭据存储，也没有还原编码或混淆内容。源码中的运行条件表示预期调用路径，运行成功及插件版本兼容仍未验证。逐卡分类由阅读判断完成，脚本只枚举字段与调用位置。

## 八个机制样本

### C002：初始化任务写聊天变量

`/data/extensions/xiaobaix-tasks/tasks/1` 配置 `triggerTiming=initialization`、`disabled=false`、`buttonActivated=false`。其 `commands` 调用 `STscript('/setvar …')`，分别写 `lust_level=10`、`active_members=8`、`user_reputation=0` 和 `user_title`。任务 0 的代码块为空，不能算第二项业务功能。这里能确认的是初始化脚本声明及写入参数；插件实际何时执行、重复初始化是否覆盖存量状态尚未运行验证。

这张卡展示了不依赖 MVU 的命名变量初始化。迁移时应把四个字段及初始化时机显式记录，不能因为存在任务扩展就推断它调用额外模型。三条正则位于 `/data/extensions/regex_scripts/0` 至 `/2`，均启用且 `markdownOnly=true`，属于显示处理。

### C026：消息驱动终端与状态快照并存

`/data/extensions/regex_scripts/5/replaceString` 的 `populateCharacterData()` 调用 `getAllVariables()` 读取 `stat_data`；初始化等待 `waitGlobalInitialized('Mvu')`，并在 `Mvu.events.VARIABLE_UPDATE_ENDED` 后重绘。这个状态栏读取的是变量快照。

同卡 `/data/extensions/regex_scripts/6/replaceString` 至 `/10/replaceString` 则调用 `getChatMessages(getCurrentMessageId())`，从当前消息正文解析回收、交易、拍卖、报名、结算界面。第 7 项还读取 `stat_data.信用筹码`，第 8 项读取 `stat_data.存款`，第 9 项读取 `stat_data.奴隶列表`。不同面板的字段名并不统一，转换器需要对照 schema 才能确认余额字段是否存在；显示出交易按钮或金额不构成已经执行扣款的证据。

`/data/extensions/tavern_helper/scripts/0/content` 定义 Zod 结构并调用 `registerMvuSchema(Schema)`；第 1 项只导入远程 MVU bundle。远程 bundle 的更新解析、事务语义和成功运行均未核实。该样本要求自有卡格式分别声明“从消息抽取的展示数据”和“持久状态读取”，避免把模型叙述的结算报告当成已经提交的状态变更。

### C035：论坛按钮提交文本，浏览器保存显示偏好

`/data/first_mes` 为主页占位文本，卡内共有 25 条正则。`/data/extensions/regex_scripts/5/replaceString` 的购物确认路径构建 `/send … | /trigger`，再调用 `triggerSlash(cmd)`；第 6 项的 `sendMessage()` 也把输入框文本转为相同命令链。实际可见调用说明这些操作提交用户文本并触发模型，不能据商品名称推断存在确定性交易引擎。

这两个界面读取和写入 `localStorage` 的 `forum-theme`、`forum-font-size`，并监听 `storage` 事件同步显示。`/data/extensions/tavern_helper/scripts/1/content` 注册 Zod schema，包含额度数值约束。第 0、2 至 6 项是远程导入，包括 MVU、设置调整和论坛增强脚本；本地只有导入语句，本文不把它们的文件名当成已验证实现。

迁移需求包括按钮发送、独立显示偏好和可追踪的模型调用；额度如何扣减仍需远程实现或运行证据。

### C065：回复后辅助分析与世界书写入

`/data/extensions/xiaobaix-tasks/tasks/2` 为启用的 `RUBY分析`，配置 `triggerTiming=after_ai`、`floorType=llm`、`interval=1`、`buttonActivated=false`。其 `commands` 读取 `SillyTavern.getContext().chat`，通过 `/getvar` 与 `/setvar` 维护 `ruby_cycle_counter`、`ruby_internal_cursor`，按任务配置决定本轮是否分析。保存的默认方案位于 `/data/extensions/xiaobaix-tasks/tasks/2/x/RubyAnalyzer/presets/0`，两个启用任务均指定周期位置 10。顶层旧任务配置与方案配置同时存在，读取者需要保留方案选择关系。

`callAI()` 构造 `/xbgenraw`，经 `STscript(cmdMain)` 调用模型；流式路径等待消息事件，非流式路径提取返回文本。源码确有编码提示词的构造函数，本研究没有运行该函数或还原任何编码数据。脚本随后查找或创建聊天世界书条目，以 `/setentryfield` 写内容、关键词、常驻、启停、位置、排序及条件字段，并调用 `saveWorldInfo(chatWorldbook, worldData, true)`。这是额外生成后写知识库的实际源码链路。

第 1 项 `RUBY面板` 读取 `extensionSettings`，保存任务/API 配置，点击模型列表时调用 `fetch(.../v1/models)`。第 0 项楼层修复任务通过 `/xbqte RUBY分析` 重新触发分析。上述代码需要宿主扩展与设置 API；本研究没有读取实际设置或调用服务。迁移需要带输入范围、模型预算、输出条目目标和幂等记录的辅助 Agent，而单纯导入人物设定会丢失这项功能。

### C068：提示词控制器、状态约束与行动提交分工

`/data/character_book/entries/104/content` 读取感情、阶段数值及事件布尔值，通过 `getwi()` 选择条目并 `print()` 注入。第 106 项读取日期、路线、阶段和事件记录，包含较完整的条件控制；第 122 项根据 `stat_data.世界.开局模式` 选择开局前提。它们是请求组装时的内容选择源码，不能把读取事件字段误写成已经推进事件。

`/data/extensions/tavern_helper/scripts/0/content` 的 Zod schema 包含数值转换、范围裁剪及默认值。`/data/extensions/regex_scripts/5/replaceString` 在 MVU 更新事件后刷新状态和选项；选项提交调用 `createChatMessages([{role:'user',message:text}], {refresh:'affected'})`，然后 `triggerSlash('/trigger')`，并检查当前消息是否为末条消息。第 6、7 项正则补正文闭合标签及状态栏占位符，属于输出修复链。

这张卡需要同时保留状态验证、提示词控制器、公开显示和用户动作这四个步骤。动作按钮当前明确创建用户消息；后端接入需要保持消息创建与随后生成的关联，并验证历史消息上的按钮不会重复提交。

### C083：独立手机会话与可选正文注入

`/data/extensions/tavern_helper/scripts/0/content` 用 `eventOn(getButtonEvent('りん的LINE账号'), …)` 打开手机界面。点击发送后，`genRawFn` 指向 `generateRaw`，以 `ordered_prompts` 加入人物描述、人物性格、当前日本时间、手机预设、可选用户人设、主聊天历史、最近 20 条手机记录和当前输入；调用参数为 `max_chat_history:3`、`should_silence:true`，并可指定 `custom_api`。

手机历史保存在顶层窗口 `localStorage` 的 `rin-phone-history`，用户资料保存在 `rin-user-persona`，开关保存在 `rin-join`。脚本还保存自定义服务设置；本文仅检查字段访问源码，没有读取任何实际设置值。生成成功后先清理回复标签，再写入手机历史。失败分支也向手机历史追加错误回复，因此历史内容并不等于成功模型输出集合。

`/data/character_book/entries/5/content` 是 EJS：仅当 `rin-join` 为 true 时读取手机历史，并把记录 `print()` 到正文请求。该行为会跨越显示与提示词边界。迁移需要独立对话记录、独立生成与显式注入策略；浏览器存储键没有会话 ID，跨会话隔离不能从本地源码得到保证。

### C098：卡内写卡工具读取世界书与历史

`/data/first_mes` 是界面占位符；`/data/extensions/regex_scripts/1/replaceString` 包含大型 HTML/JavaScript 前端。`getCurrentCharacterPrimaryWorldbook()` 获取当前角色主要世界书名称，再调用 `getWorldbook(primaryWorldbookName)`；历史读取调用 `getChatMessages('1-' + lastMessageId)`。用户操作通过 `triggerSlash('/send …|/trigger')` 发送创作请求。源码同时包含 `fetch('testMessage_data.json')` 及开发分支的 `fetch('./testWorldBooks.json')`；这些相对资源在本轮没有读取或验证。

世界书 `/data/character_book/entries/16/content` 与 `/17/content` 保存状态栏元数据模板，其中可见消息读取、按钮发送和浏览器显示偏好代码。它们是创作工具提供的模板文本；模板中出现函数不说明宿主已经执行这些函数。转换器需要保留“供输出的代码模板”与“当前卡可执行前端”的角色差异。

迁移价值是可复用的创作工作流与资源读取接口。当前证据确认了读取世界书、读取聊天、发送生成请求，尚未确认它通过宿主 API 把生成结果直接保存为角色卡文件。

### C113：开场选择写世界书，EJS 再按状态选择章节

`/data/extensions/tavern_helper/scripts/2/content` 监听 `tavern_events.MESSAGE_SWIPED`，同时每 500 毫秒调用监测函数；后者用 `TavernHelper.getChatMessages(0,{include_swipe:true})` 读取开场 `swipe_id`。检测到切换后，脚本根据映射判断剧情/沙盒模式，调用 `getCurrentCharPrimaryLorebook()`、`getLorebookEntries(book)` 并以 `setLorebookEntries(book, mods)` 更新条目 `enabled`。初始化延迟和 `pagehide` 清理均在源码中可见。

另一条路径 `/data/character_book/entries/18/content` 通过 `getvar('stat_data.当前模式')` 与 `getvar('stat_data.剧情.当前卷')` 决定 `getwi()` 引用；`/data/extensions/tavern_helper/scripts/1/content` 注册模式与剧情/沙盒状态的 schema。开场索引驱动的世界书开关与状态驱动的 EJS 选择不是同一个状态源，静态研究不能证明两者始终同步。

自有格式应明确开场选择事件、会话模式状态与知识启用范围。原脚本写的是所取主世界书，不能假定该修改仅属于当前会话；迁移后的会话隔离需要实际验证。

## 世界书时效与包含组补充

C059 的 `/data/character_book/entries/27`、`28`、`29`、`31`、`32`、`35`、`37`、`39`、`40` 均启用，且各自 `/extensions/delay` 为 1。它们构成实际使用时效配置的样本；本组没有执行本地宿主的时效引擎，因此不能把该值直接等同于“每隔一轮触发”，也不能当成无效元数据丢弃。

C107 的多个条目共享 `/extensions/group`，例如 entries 9、13 使用同一值，另有 `group_weight=100` 和 `group_override=false`。这是世界书包含组字段，必须结合宿主选取规则研究，不能转换成知识目录分类后宣称行为保留。启用与停用条目均可能保存组字段。
