# 本地 SillyTavern 角色卡调研结论

## 范围与读取方法

本轮唯一角色卡来源是用户指定的 `/srv/data/mac bookpro old/AI/SillyTavern`。此前公开网络样本属于其它资料，本轮结论以本地证据为准，[原转换器计划](../../plans/native-card-converter/design.md)及[格式草案](../../plans/native-card-converter/native-card-v1.schema.json)保持不变。

默认用户 `data/default-user/characters` 有 113 个 PNG 文件，开发用户 `data/dev/characters` 有 2 个，共 115 个卡文件。数量包含同作品不同版本和不同用户目录，表示文件数，不表示 115 个独立作品。三名队员分组覆盖 39、38、38 个文件，各组逐卡结构盘点，并分别深读至少八张不同机制的卡。

本轮直接读取 SillyTavern 已生成的 `data/_cache/characters` JSON 文本，按原 PNG 相对路径和修改时间关联，115 个文件均找到对应缓存。缓存键规则可见本地 `src/endpoints/characters.js` 的 getCacheKey。原 PNG、缓存、时间、卡 ID 和本次读取副本路径均记录于 [inventory.json](inventory.json)。研究者没有解码 PNG、运行角色脚本、读取聊天或凭据，也没有调用模型。

本地 `src/character-card-parser.js` 的写入函数会额外生成 `chara_card_v3` 数据，读取函数优先选择 ccv3。因此，115 个缓存都声明 V3 是本地保存形态的证据，原作者制作时的 V2/V3 版本仍须另行确认。

## 自有卡格式与 Agent 的扩充方向

自有卡除人物、世界书、文件和变量 schema 外，还应研究以下可交付的行为定义：

1. **动作定义**：参数、前置条件、状态读写范围、计算模块、结果回执，以及是否接续生成。
2. **开场方案**：正文、初值、绑定人设输入、知识条目启停和初始化动作的共同选择。
3. **事件和任务定义**：何时执行、间隔按什么计数、依赖哪些前序结果、调用哪个模型槽、结果保存到哪里。
4. **辅助会话与知识归属**：主/辅助对话、会话或分支知识覆盖层、持久与单轮提示词注入分别声明。
5. **状态处理顺序**：默认值、强制转换、变量 Agent 提案、确定性计算、验证和快照提交分别表达。
6. **转换来源与损失记录**：原卡、绑定世界书、远程依赖、禁用功能分别记录；来源版本冲突由使用者明确处理。

Agent 适合阅读混合规则、判断正文事实、生成辅助总结或记忆提案。数值计算、日期推进、计数、条目开关和确定的条件判断应由程序执行。卡使用了某插件并不意味着系统需要创建同名 Agent；实际功能能映射到现有 API 时，转换器应生成对应的原生配置。

建议优先支持本地已经存在的开场与知识联动、状态动作、变量规则拆分、周期辅助任务和辅助对话。历史多楼层改写、特定检索宿主和自动更新外部脚本需要分别验证，当前证据尚不足以承诺原样转换。
