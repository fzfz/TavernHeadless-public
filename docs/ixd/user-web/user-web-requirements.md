# 用户 Web 需求规格

## 1. 规格范围与入口

1. 本文规定用户 Web 的产品行为。术语采用[用户演绎领域](../../../apps/user-web/CONTEXT.md)；系统界面与角色演绎内容区采用[角色显示领域](../../../packages/shared/CONTEXT.md)的定义。
2. 当前交互原型与验收范围见[阶段 7 原型验收](phase7-review-master.md)；[初步布局](prototype/index.html)保留流程演示入口，设计阶段状态由 [progress.json](progress.json) 记录。
3. 各项设计的用户需求依据、后端能力和接入状态统一见[功能依据](feature-basis.md)。阶段文档引用该表，并按当前代码更新接入结论。
4. 设备覆盖与原型交付范围采用[阶段 1 第 2 节](phase1-context.md#2-目标平台与实现基础)的约定。

## 2. 页面与功能范围

1. 注册、登录页面提供账号创建与登录入口；用户中心提供账号资料查看、编辑和退出登录。
2. 角色广场提供角色卡筛选、详情和开始演绎入口。
3. 演绎人格页面提供人格列表、创建、编辑、删除和默认人格设置；用户中心提供该页面的入口。
4. 开始演绎流程提供演绎人格与角色开场选择，成功创建会话后进入独立演绎页面。
5. 历史演绎页面提供会话列表、加载、继续演绎与删除；继续演绎打开对应会话。
6. 单个演绎页面支持发送、停止生成、重新生成、切换候选回复、续写、编辑和删除消息，以及从消息建立分支。核心交互参考 SillyTavern。

## 3. 演绎人格归属与生命周期

1. 一个用户账号可以拥有多个演绎人格；每个演绎人格归属于一个用户账号。
2. 用户可以自行设计各人格的姓名和完整人设描述。用户账号的昵称与人格姓名分别保存。
3. 人格列表、详情、创建、编辑、删除和默认人格设置均以当前登录用户为归属范围。切换账号后，页面显示切换后账号的人格；重新登录和刷新恢复该账号已保存的资料。
4. 新注册用户的人格库为空。开始演绎前，页面引导该用户创建演绎人格。
5. 每个用户最多设置一个默认人格，且该人格必须属于本人。开始演绎时优先选中默认人格，用户可以改选自己拥有的其他人格。
6. 创建会话时，后端校验所选人格的归属与可用状态，并保存人格快照。角色发布配置中的试聊人设由管理端使用；用户演绎采用用户本次选择的演绎人格。
7. 人格资料更新用于之后创建的会话。历史加载、继续演绎和从消息建立分支均沿用原会话的人格快照。
8. 删除人格后，该人格退出新演绎的选择列表，已有会话仍可读取其人格快照。删除默认人格时，用户 Web 自动将列表中第一个剩余人格设为默认人格；删除最后一个人格后，默认人格为空，页面展示创建入口，并在开始新演绎时引导用户先创建人格。
9. 人格及会话接口必须校验登录身份与资源归属。另一用户即使取得资源标识，也无权读取、修改、删除或绑定该资源。

## 4. 独立演绎页面与渲染职责

1. 演绎页面使用独立页面布局。角色广场、用户中心等页面的公共侧栏和顶栏仅用于这些页面；演绎页保留返回历史、当前会话身份和演绎设置等必要操作。
2. 角色卡前端 Runtime 负责加载角色交付的模板、样式和脚本，并渲染角色演绎内容区。角色可以定义各自的布局、背景、状态显示和剧情交互。
3. 用户 Web 负责账号、人格选择、会话创建、历史管理、生成请求及通用聊天操作。角色通过 Runtime 提供的接口使用这些能力；系统聊天组件可以按角色布局挂载。
4. 默认对话模式由用户 Web 的聊天组件渲染。自定义角色布局通过 Runtime 渲染，并在使用通用聊天时嵌入该组件。
5. Runtime 的调用和生命周期遵循[Runtime 架构](../../character-authoring/runtime-architecture.md)，开场契约遵循[系统开场选择](../../character-authoring/session-openings.md)。

## 5. 当前实现与验收入口

1. 用户 Web 实现位于 [apps/user-web](../../../apps/user-web/CONTEXT.md)，注册、人格、角色选择、会话与消息通过官方 SDK 访问 API。接口消费路径统一见[功能依据第 2 节](feature-basis.md#2-功能与数据来源)。
2. 启动条件、浏览器逐页结果、故障恢复和模型调用范围见[实现验收](implementation-acceptance.md)。

## 6. 验收要求

1. 用户 A 创建至少两个人格并切换默认人格；开始演绎时可选择其中任意一个。用户 B 的人格列表与选择器仅显示 B 的资料。
2. A 退出后登录 B，再重新登录 A；A 的人格内容、默认选择和会话在刷新后保持一致。
3. 分别使用 A 的两个人格创建会话，核对页面身份、保存快照与实际请求。使用 `respond/dry-run` 阅读姓名及完整描述的展开结果，验收方法见 [AGENTS.md](../../../AGENTS.md) 的“演绎调试与验收”。
4. 修改或删除源人格后，加载历史、继续演绎和创建分支，核对第 3 节规定的快照行为。
5. 以 B 的登录身份访问 A 的人格和会话标识，分别验证列表、详情、编辑、删除及创建会话的归属校验。
6. 删除默认人格且仍有剩余人格时，按第 3 节第 8 项核对默认选择；删除最后一个人格后刷新，验证空人格库、默认人格为空和开始新演绎时的创建引导。
7. 分别进入自定义布局和默认对话模式的角色会话，验证独立页面、系统操作、Runtime 渲染、历史恢复和返回入口。
8. 在桌面和手机浏览器中分别验收第 2 节的全部功能，以及本节第 1—7 项。桌面端核对鼠标与键盘操作；手机端核对触控操作、软键盘展开时的输入与发送、长文阅读及角色 Runtime 内容的可用性。
