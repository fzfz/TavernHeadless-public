## 3. 六个视角的评审

### 3.1 首次使用者

1. 角色浏览、详情与开始演绎的路径连续，登录后可以回到原目标。
2. 人格选择与会话人设查看分别说明使用者准备扮演和当前扮演的人物。

### 3.2 高频使用者

1. 历史搜索、重命名和批量删除覆盖日常整理任务。
2. 候选回复、续写和会话内分支覆盖持续演绎任务，键盘操作可从附录 F 查找。
3. 接入真实长历史后，按 P15—P18 的数据策略验证分页与位置恢复。
4. 接入跨设备偏好后，按功能依据验收默认人格的恢复行为。

### 3.3 辅助技术使用者

1. 页面规格定义焦点顺序、弹层焦点范围和关闭后的焦点归位。
2. 视觉变量提供浅深色映射，原型已有大字、触控范围及减少动态效果的验证记录。
3. 按原型验收第 2.2 节补充系统读屏的真实操作验收。
4. 在手机浏览器上核对软键盘、后台恢复和输入法对发送行为的影响。

### 3.4 前端开发者

1. 页面组件编号映射到共用组件，视觉变量采用结构化配置。
2. 独立会话页面、角色 Runtime 和宿主覆盖层的职责有对应规格。
3. 接入账号与默认人格时，按功能依据核对身份归属和保存位置。
4. 接入写入与生成接口时，按[任务流程 S02](phase3-userflows.md)核对操作结果的证据和恢复路径。

### 3.5 测试人员

1. 页面编号可关联规格、路由与原型验收结果。
2. 原型记录覆盖失败、待确认、部分成功、账号隔离和刷新恢复。
3. 真实接口接入后，按功能依据核对请求、保存结果与页面显示。
4. 使用实际发布角色验收 Runtime 布局、角色数据与消息操作的组合。

### 3.6 视觉设计者

1. 通用界面采用同一套字体、间距和主题变量，双端布局分别适配。
2. 角色内容有独立呈现范围，宿主反馈保持可辨认。
3. 提供实际发布角色使用的媒体后，按视觉设计第 4 节验收裁切、长标题与加载失败。
