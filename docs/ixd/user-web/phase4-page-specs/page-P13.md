# P13：开始演绎（桌面 Web）

## 1. 页面概述

1. 页面目标是让用户确认本次演绎的人格和开场，并打开创建成功的会话。所属模块为角色演绎，层级为 L2；入口为 P01、P03，成功目标为 P17。
2. 页面采用[阶段 3 第 5 节 F03](../phase3-userflows.md)。身份访问、提交核对分别引用该文档第 8.1、8.2 节 S01、S02。
3. 人格归属、默认选择和快照采用[需求规格第 3 节](../user-web-requirements.md)，开场内容采用[系统开场选择](../../../character-authoring/session-openings.md)。

## 2. 页面布局

1. 桌面站点侧栏和顶栏沿用阶段 2 第 4.1 节。主区域使用以下结构；人格与开场是两个有标题的单选组。

```text
站点侧栏 │ 站点顶栏
         │ 返回来源 · 开始演绎
         │ 当前角色名称及摘要
         │ 人格单选组           │ 开场单选组
         │ 创建人格             │ 所选开场的正文预览
         │ 本次选择摘要 · 提交反馈 · 开始演绎
```

2. 主区域统一纵向滚动。开场预览随内容展开，长文保留完整阅读入口。底部提交区可粘附在主区域可见底部，正文留出对应空间，最后一个选项与焦点提示始终可见。
3. 可用宽度不足以并排阅读时，两组依次排列；用户选择保持不变。角色名称与本次选择摘要优先于装饰信息。

## 3. 组件清单

| 编号 | 组件     | 类型／区域                     | 触发与结果                               |
| ---- | -------- | ------------------------------ | ---------------------------------------- |
| C01  | 返回来源 | 导航／页首                     | 返回进入选择页的角色列表或详情           |
| C02  | 当前角色 | 只读摘要／页首                 | 展示本次发布资源的角色名称与介绍         |
| C03  | 演绎人格 | 单选组／左侧                   | 选择本人的一个人格，显示所选人格完整描述 |
| C04  | 创建人格 | 链接／人格组                   | 打开 P11，携带返回目标                   |
| C05  | 角色开场 | 单选组／右侧                   | 选择开场，更新预览                       |
| C06  | 开场预览 | 可展开文本／右侧               | 阅读或收起所选开场全文                   |
| C07  | 开始演绎 | 主按钮／提交区                 | 核对选择并创建会话                       |
| C08  | 请求反馈 | 状态区域／对应失败区域或提交区 | 展示进度、原因、重试读取或核对结果入口   |

## 4. 交互行为详述

1. **C01**：点击、键盘激活均返回来源，直接访问时回角色广场。提交后离开页面的恢复行为见第 7 节；创建尚未发出时保留当前标签页内的选择。
2. **C03**：有效的上次选择优先保留；首次进入按需求规格选择默认人格。缺少有效默认值时显示“请选择本次演绎人格”。单选组支持方向键移动选项、空格选择；每项包含姓名、选中标识和可读取的描述。选择只影响本次开始任务。
3. **C04**：创建期间保留角色与开场选择。P11 成功返回后重新读取人格集合并选中新建人格；取消返回时恢复仍有效的原选择。空集合显示“先创建一个演绎人格”及同一创建入口。
4. **C05、C06**：首次加载使用角色发布内容中的有效默认开场；默认标识失效时提示用户选择。开场条目显示标题、简介及有数据支持的类型；单选与全文展开分别操作。展开按钮提供 `aria-expanded`；切换开场后预览回到该开场正文起点，键盘焦点留在选项。
5. **C07**：加载未完成、必选项缺失、选择已失效或正在提交时禁用，并在邻近位置说明原因。按钮可用时，点击或键盘激活仅提交一次；当前页面固定本次选择并显示“正在创建演绎…”。收到会话标识后打开该会话；会话读取失败时提供“重新打开演绎”。
6. **C08**：读取失败只重试对应资源；明确未创建时保留选择，显示可操作原因并恢复提交；结果待确认时提供“核对创建结果”和“返回历史”。状态转换采用 S02，文案“创建结果尚未确认，请先核对”与核对按钮保持可见。
7. 所有可操作项具有悬停、按下和键盘焦点反馈；选中与禁用状态同时使用文本或语义属性表达。整行单选的标签可点击，全文中的文本仍可选择与复制。

## 5. 页面状态流转

| 状态           | 进入条件                   | 页面呈现                                     | 用户操作与后续状态             |
| -------------- | -------------------------- | -------------------------------------------- | ------------------------------ |
| 加载中         | 初次访问或刷新             | 角色、人格、开场分别显示读取状态，提交不可用 | 返回来源；读取成功转可选择     |
| 部分就绪       | 其中一组已读取             | 展示成功数据，失败组保留局部反馈             | 重试失败组；全部就绪后核对选择 |
| 可选择         | 数据就绪                   | 单选项、当前预览和提交摘要                   | 选择有效组合后可提交           |
| 人格为空       | 当前账号的人格集合确认为空 | 创建引导，保留开场                           | 进入 P11，返回后更新集合       |
| 开场不可用     | 发布资源没有可用开场       | 显示原因及返回角色入口                       | 重读资源或返回重选             |
| 提交中         | 请求已发出                 | 固定选项，显示创建进度                       | 等待结果或按第 7 节离开        |
| 已创建         | 返回确定会话标识           | 打开对应会话                                 | 读取失败仍重试同一会话         |
| 明确失败       | 服务端拒绝                 | 对应原因与保留的有效选择                     | 修正失效选项后重新提交         |
| 结果待确认     | 响应缺失或无法关联         | 保留选择和核对入口                           | 按 S02 核对，确认后转相应状态  |
| 身份或访问异常 | 身份失效、角色不可访问     | 按 S01 转 P05 或 P22                         | 登录恢复后重新校验选择         |

## 6. 动效说明

1. 选择标识、按钮状态及展开提示采用 `--motion-duration-feedback` 与 `--motion-easing-standard`；预览切换以内容替换和轻量淡入表达，避免移动整个选择组。
2. 进入会话采用 `--motion-duration-page` 与 `--motion-easing-standard`。减少动态效果偏好启用时直接呈现状态；加载过程始终保留文字说明。

## 7. 数据策略

1. 角色发布资源与当前账号的人格集合分别读取并记录成功状态。页面只使用与当前账号、角色及发布标识匹配的响应更新内容。
2. 人格集合按实际接口分页追加，并提供“加载更多”和已加载范围；默认人格若未出现在当前页，须读取其有效记录后才能选中。开场集合按发布资源提供的完整清单展示；正文预览在选定后加载，失败时仅重试预览。
3. 当前标签页内保留来源、选择及展开状态；进入 P11 再返回、浏览器前进后退均先恢复这些内容，再重新核对资源。账号切换按 S01 隔离；提交采用后端校验结果。
4. 页面再次可见时重新核对人格与发布资源。选项被删除或发布内容改变时，标注失效项并要求用户重新确认选择；其余有效选项保留。
5. 请求发出后记录待核对操作；离开和刷新后通过 S02 恢复。创建已确认时保存返回的会话标识，继续读取该会话。创建响应丢失时所需关联证据、默认人格跨设备保存，以及发布取值顺序均按[功能依据](../feature-basis.md)接入验收。
6. 离线时保留已读取的内容供阅读，提交区显示“连接恢复后再开始演绎”；恢复连接后重新读取必要资源。页面展示当前可观测状态，数据新鲜度以最近一次成功读取为准。

## 8. 适配说明

1. 页面缩窄、浏览器放大和长姓名场景下允许换行；单选标识与姓名保持关联。人格描述与开场全文使用自然段，图片加载失败时保留角色名称。
2. 键盘顺序依次为返回、人格组、创建、开场组、全文展开、提交与反馈操作。语义使用 `main`、标题、`fieldset`、`legend`；必选状态和错误说明通过可访问描述关联。提交结果用礼貌播报，校验失败将焦点移至首个失效选择组。
3. 触屏桌面设备使用 `--size-target-min` 与 `--space-control-gap` 表达点击范围要求；鼠标悬停提示补充截断信息，完整内容也可通过焦点和点击获取。原生复制、文本选择和浏览器快捷键保持可用。
4. 手机专用组织见 [P14](page-P14.md)。颜色对比、焦点可见性、主题下的可读性及字号放大由阶段 6、7 使用实际界面验收。

## 10. 特定场景微交互说明

1. **切换开场**：行为采用第 4 节 C05、C06。选中标识先响应，预览区随后呈现读取反馈与正文；正文替换时只淡入内容，保留外部选项的位置。切回原项采用同一反馈顺序，焦点规则沿用第 4 节。
2. **确认创建**：行为采用第 4 节 C07、C08。按钮状态与邻近反馈同步更新；错误和核对提示使用相同反馈位置，使用户能够沿原操作位置继续处理。
3. 两个场景均使用第 6 节 token，减少动态效果时直接替换。声音与振动关闭；行为恢复按各自交互条目执行。
