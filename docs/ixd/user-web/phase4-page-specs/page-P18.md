# P18：演绎会话（手机 Web）

## 1. 页面概述

1. 页面属于角色演绎独立 L2，入口为 P14、P16 或会话地址；返回目标为 P16。共用行为采用 [P17](page-P17.md)；本文规定手机布局和浏览器生命周期适配。
2. 人格查看与标题编辑分别进入 P20、P19，消息删除进入 P21。角色内容和通用聊天的职责引用 P17 第 1、2 节。

## 2. 页面布局

1. 手机会话占据可用视口，按以下结构组织。

```text
返回历史 │ 会话标题 │ 演绎设置
角色名称 · 本次演绎人设
运行与恢复反馈（有状态时显示）
角色 Runtime 内容区域
  角色自定义手机布局
  挂载通用聊天：记录／消息操作／输入与发送
```

2. 默认对话模式让消息列表占据主要阅读区，输入区位于通用聊天组件底部。角色自定义模式使用角色提供的手机布局；宿主保留顶层返回与恢复入口，通用聊天在角色指定区域内适配可见视口。
3. 输入聚焦后，聊天输入区在键盘上方保持可见，消息区调整可用高度；正在阅读更早消息时保持消息锚点。键盘关闭后恢复阅读空间及既有位置。
4. 消息菜单在点击目标消息的“消息操作”后打开；长内容菜单可滚动。P19、P20、P21 的覆盖层位于角色内容上方，关闭后恢复触发位置。长标题允许截断，完整标题可在 P19 阅读。

## 3. 组件清单

| 编号 | 组件       | 手机位置           | 操作                         |
| ---- | ---------- | ------------------ | ---------------------------- |
| C01  | 会话导航   | 顶部               | 返回 P16、打开 P19、打开 P20 |
| C02  | 运行反馈   | 导航下方           | 阅读状态、停止或核对结果     |
| C03  | 角色内容   | 主要视口           | 角色规定的触控剧情交互       |
| C04  | 对话记录   | 通用聊天内部       | 阅读、加载更早、回到最新     |
| C05  | 消息操作   | 每条消息的可见入口 | 打开该条消息的操作菜单       |
| C06  | 候选回复   | 目标回复附属区     | 上一条、下一条与序号         |
| C07  | 消息编辑   | 目标消息处         | 编辑、保存与取消             |
| C08  | 输入与发送 | 通用聊天底部       | 多行输入，点击发送           |
| C09  | 停止生成   | 运行时可达区域     | 请求停止当前运行             |

## 4. 交互行为详述

1. **C01—C07、C09** 的操作结果及可用条件引用 P17 第 4 节。手机菜单逐项列出可用动作和临时不可用原因；点击菜单外或返回键关闭，焦点回到对应消息。删除进入 P21 后再按其关闭规则处理。
2. **C08** 使用软键盘 Enter 换行，发送通过独立按钮完成；输入法组词保持原生行为。外接键盘支持 Ctrl+Enter 或 Cmd+Enter 发送，并支持 Shift+Enter 换行；发送按钮的可访问说明包含快捷键。
3. 发送后保留输入焦点与键盘，方便准备下一条草稿。停止入口在键盘展开时保持可达；生成期间发送资格、草稿及正文保存采用 P17 第 4.2 节。
4. 候选切换使用明确方向按钮与当前序号；消息阅读保留横向内容自身的滚动行为。文本长按用于选择复制，消息操作使用独立按钮。
5. 打开人设或设置时收起键盘，保存聊天输入与阅读位置；关闭后恢复原焦点，键盘是否自动出现遵循浏览器行为。消息编辑保存失败时保留文本并将错误说明带入视口。
6. 返回历史采用 P17 第 4.1 节 C01，站内离开的草稿处理采用 P17 第 4.3 节第 6 项。手机系统返回与浏览器后退在弹层打开时先关闭弹层；页面刷新按第 7 节恢复会话。

## 5. 页面状态流转

1. 业务状态采用 P17 第 5 节；手机特定呈现如下。

| 状态                 | 手机呈现与恢复                                       |
| -------------------- | ---------------------------------------------------- |
| 会话或 Runtime 加载  | 顶部导航持续可达，内容区显示各自进度                 |
| 就绪或记录为空       | 显示角色手机布局及对应聊天内容状态                   |
| 生成、停止或保存核对 | 键盘展开时仍显示状态和停止或核对入口                 |
| 编辑中               | 编辑控件位于可见视口，保存失败保留正文               |
| 结果待确认或离线     | 保留已读正文与草稿，显示核对入口                     |
| Runtime 失败         | 显示可读正文、重新加载和返回历史                     |
| 切到后台再恢复       | 保留本地输入，重新读取运行和保存结果后恢复可执行操作 |
| 身份或访问失效       | 按 S01 进入 P05 或 P22                               |

## 6. 动效说明

1. 聊天、菜单、候选和滚动反馈沿用 P17 第 6 节 token。软键盘出现与消失跟随浏览器视口变化，页面避免再叠加位移动画。
2. 角色动画的适配采用 P17 第 6 节。

## 7. 数据策略

1. 消息分页、草稿、运行核对和账号隔离引用 P17 第 7 节。
2. 页面进入后台时保留当前草稿及阅读锚点；浏览器暂停连接或回收页面后，恢复目标会话与分支并按 S02 核对。运行、停止及保存均以读取结果恢复，用户可在等待期间阅读已有正文。
3. 网络切换后先核对已有运行，确定结果后再恢复发送、候选切换及消息管理。页面首次访问且无可读内容时，显示读取失败与重试；已取得内容时保留成功部分。
4. 角色资源版本按当前会话读取；手机方向、键盘及视口变化只更新布局。数据归属与固定资源规则保持 P17 的约定。

## 8. 适配说明

1. 可见视口、安全区域和浏览器工具栏共同确定可用高度。纵横屏切换、字号放大和长文本保持通用导航、输入、停止及菜单可达；长代码或表格在内容内部滚动。
2. 触控区域及间距使用 `--size-target-min`、`--space-control-gap`；发送、停止和消息菜单各自拥有独立目标。角色剧情控件采用相同可操作性要求，具体样式由角色提供。
3. 屏幕阅读顺序为导航、运行反馈、角色内容、聊天记录和输入。菜单及弹层管理焦点，关闭后返回触发点；生成状态播报沿用 P17 第 8 节。外接键盘可遍历全部操作。
4. 输入或编辑控件获得焦点后，控件与关联错误进入可见视口；键盘遮挡测试覆盖默认对话和自定义角色布局。对比度、实际点击范围和主题可读性在阶段 6、7 验收。

## 10. 特定场景微交互说明

1. **输入聚焦与键盘展开**：布局行为采用第 2 节第 3 项。聊天区域随浏览器可见视口变化重新排布，过渡由浏览器驱动；用户连续开关键盘时，以当前视口为准更新布局。
2. **消息菜单**：行为采用第 4 节第 1 项。菜单展开使用第 6 节 token，关闭过程中用户再次触发同一入口时，以最近操作决定显示状态。
3. 两个场景均关闭声音与振动；减少动态效果时直接呈现。生成、停止、阅读追加及候选切换的微交互采用 P17 第 10 节，反馈位置使用本页第 2 节。
