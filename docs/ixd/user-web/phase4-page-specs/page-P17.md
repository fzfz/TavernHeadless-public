# P17：演绎会话（桌面 Web）

## 1. 页面概述

1. 页面目标是让用户在指定会话与分支中持续阅读、输入和管理对话。所属模块为角色演绎，层级为独立 L2；入口为 P13、P15 或会话地址，返回目标为 P15。
2. 本页采用[阶段 3 第 6 节 F04](../phase3-userflows.md)及第 8 节 S01、S02。渲染职责采用[需求规格第 4 节](../user-web-requirements.md)，Runtime 生命周期采用[Runtime 架构](../../../character-authoring/runtime-architecture.md)。
3. 当前人格资料由 P20 展示，标题由 P19 编辑；两项职责见[阶段 2 页面清单](../phase2-architecture.md)。

## 2. 页面布局

1. 会话占据完整页面，外层只承载通用会话导航及运行反馈。布局如下；角色内容区域延伸到页面可用边界。

```text
返回历史 │ 会话标题 · 角色名称 │ 本次演绎人设 │ 演绎设置
会话运行或恢复反馈（有状态时显示）
┌ 角色 Runtime 内容区域 ─────────────────────┐
│ 角色提供的场景、状态、背景、剧情交互与布局   │
│ 角色指定位置挂载通用聊天组件                │
│   对话记录 · 消息操作 · 输入与生成操作       │
└───────────────────────────────────────────┘
```

2. 默认对话模式由通用聊天组件占据主要阅读区，输入区附着于该组件底部。自定义角色布局由 Runtime 决定聊天挂载位置和角色区域的滚动方式；宿主持续提供可达的返回、设置及恢复入口。
3. 通用聊天内部由消息列表纵向滚动，输入区保持可见；角色自定义阅读区需要在挂载时明确滚动容器，避免两个相邻滚动区域争用同一阅读动作。本文的消息滚动行为作用于通用聊天列表。
4. P19、P20、P21 在宿主覆盖层展示，关闭后回到原阅读位置与触发控件。Runtime 加载失败时，外层仍显示导航、失败原因和“重新加载角色页面”；已取得的正文以只读列表供阅读。

## 4. 交互行为详述

### 4.1 导航、角色内容与阅读

1. **C01**：返回历史采用 F04-D4；正在生成时显示“正在结束生成并保存…”，随后按 S02 核对。核对尚未完成时允许用户返回历史并保留待确认提示。设置和人设入口分别打开 P19、P20，保持当前会话、分支和阅读位置。
2. **C03**：角色控件的文字、布局与动作来自当前固定版本。调用通用输入或生成能力时，与 C08、C09 共用运行状态；角色控件反馈必须与实际请求状态一致。角色资源失败时执行第 2 节的恢复呈现。
3. **C04**：初次打开定位到最新保存记录。加载更早消息使用明确按钮并保持当前可见消息的锚点；追加内容仅在用户原本停留列表末尾时跟随。用户向上阅读后显示“回到最新”，激活后滚动到当前输出末尾。角色正文和人格姓名具有可读取文本。
4. 点击、悬停及键盘焦点均有反馈。消息操作可通过可见“消息操作”按钮进入；菜单打开后支持方向键选择、Enter 激活、Esc 关闭并返回触发按钮。

### 4.2 发送、停止与生成

1. **C08**：输入框支持多行、粘贴和原生文本编辑。桌面 Enter 发送、Shift+Enter 换行，输入区显示此提示；中文输入法组词期间 Enter 仅确认组词。空白输入无法发送，编辑中的正文仍保留。
2. 激活发送时固定本次文本并锁定重复提交；输入副本保留到结果确认。服务端确认接收后，页面可清空当前编辑框，但仍保留待恢复副本；明确未发送成功时恢复该文本。输入框在生成期间可用于准备下一条，发送按钮等待当前运行与保存结束后恢复。
3. **C02、C09**：等待首段时显示“正在生成…”，收到正文后逐步展示。停止点击后显示“正在停止…”，完成状态由 S02 读取确认；停止失败或结果不明时提供核对入口。正文旁的“正在生成”“正在保存”“已保存”按实际证据切换。
4. **C05 重新生成**：仅对满足接口条件的回复显示可执行入口，触发后生成新的候选。原候选保留可读，运行期间候选切换与相关写操作等待；完成后读取实际保存的候选并更新当前选中项。
5. **C05 续写**：目标回复满足条件时，在目标消息处提供入口。激活后显示该消息的续写进度，生成结束后重新读取完整保存正文。目标由操作位置明确表达；运行或保存未完成时显示等待原因。
6. 生成中发生错误时保留可见输出及其状态。尚未确认保存的文本标记“保存结果待确认”，并提供核对入口；用户输入与已保存记录分别恢复。

### 4.3 候选、编辑、删除与分支

1. **C06**：存在多个候选时显示当前序号与总数、上一条和下一条；边界方向禁用。激活时显示切换进度，成功后重读当前分支及角色数据；明确失败回到原候选，结果不明交 S02 核对。
2. **C07**：编辑使用目标消息原文，显示保存与取消；保存前按实际消息契约验证内容并在字段附近反馈。Ctrl+Enter 或 Cmd+Enter 保存，Esc 取消；已修改时取消先询问是否放弃本次编辑，用户可继续编辑。保存失败保留输入，成功后退出编辑并更新正文。编辑期间其他会改变该分支记录的操作等待。
3. **C05 删除**：打开 [P21](page-P21.md)，显示具体消息及可执行删除范围。执行后重新读取分支和角色数据；焦点落到相邻消息，列表为空时落到输入区。
4. **C05 建立分支**：入口标明“从此处建立分支”，提交前说明将从所选消息所属楼层继续。确认后按 S02 创建并打开同一会话返回的分支，显示可区分的分支标识；原分支保留。失败保留原分支及目标，结果不明提供核对入口。
5. 各项可用性依据目标消息、消息页、楼层及当前运行状态。临时不满足条件的入口显示原因；菜单仅展示当前资源支持的操作。服务端拒绝后重新读取目标状态，再确定可用操作。
6. 未提交消息或消息编辑存在时，站内离开提供“留在此页”和“离开并保留草稿”。浏览器刷新或关闭采用可用的浏览器离开提示，并按第 7 节恢复草稿；恢复后显式提示“已恢复未发送内容”。

## 5. 页面状态流转

| 状态           | 进入条件                 | 呈现与可用操作                   | 后续                       |
| -------------- | ------------------------ | -------------------------------- | -------------------------- |
| 会话读取中     | 初次打开、刷新           | 通用导航、读取反馈               | 成功后启动 Runtime         |
| Runtime 加载中 | 会话资料已取得           | 角色加载反馈，已取得正文可读     | 成功进入就绪；失败提供重试 |
| 就绪           | 资源与保存状态已核对     | 阅读、输入及符合条件的操作       | 按操作进入对应状态         |
| 记录为空       | 已确认当前分支无正文     | “当前没有对话记录”与可用输入     | 发送后读取实际记录         |
| 生成中         | 运行已开始               | 输出、停止、阅读、下一条草稿     | 结束后核对保存             |
| 停止中         | 停止请求已发出           | 原输出与停止反馈                 | S02 核对运行及保存结果     |
| 保存核对中     | 生成结束或写入响应待核对 | 正文可读，相关写操作等待         | 已确认后恢复操作           |
| 消息编辑中     | 激活编辑                 | 编辑框、保存、取消               | 成功回阅读；失败保留输入   |
| 明确失败       | 请求被拒绝               | 具体原因、可修正输入或重读入口   | 修正后重新操作             |
| 结果待确认     | 断线或证据不足           | 保留可读内容、核对入口及返回历史 | 按 S02 处理                |
| 部分读取失败   | 正文、角色资源之一失败   | 展示成功部分、局部重试           | 补齐后恢复相应操作         |
| 身份或资源失效 | S01 校验失败             | 登录恢复或 P22                   | 重新读取归属与资源         |

## 6. 动效说明

1. 消息附属菜单、行内编辑及运行状态使用 `--motion-duration-feedback`、`--motion-easing-standard`。加载更早消息保持锚点；普通流式正文直接追加，避免逐字动画叠加。
2. “回到最新”采用 `--motion-duration-scroll`、`--motion-easing-standard`；主动阅读期间保持位置。减少动态效果偏好启用时直接定位和切换，反馈文字保持完整。
3. 角色内容的动画由 Runtime 读取浏览器减少动态效果偏好并适配。宿主通用导航、错误和停止入口的可见性持续保持。

## 7. 数据策略

1. 读取按账号、会话、分支及固定角色版本归属。历史恢复采用会话保存的分支与人格快照；具体快照规则引用需求规格第 3 节。会话读取成功后再启动对应 Runtime。
2. 消息按实际接口分页读取，列表起始处提供“加载更早消息”。分页失败保留当前列表并允许重试；未读完时显示仍可加载的状态。大量正文采用分段呈现或保留锚点的列表优化，并保留辅助技术访问已加载内容的能力。
3. 消息修改、候选切换及分支创建在确定结果后重读相关记录与角色状态。过期响应只用于其原请求目标；页面以当前账号、会话和分支匹配后更新。Runtime 挂载与卸载遵循架构文档的生命周期。
4. 未发送内容、消息编辑副本和阅读锚点保存于当前标签页的账号与会话、分支范围。重新登录相同账号后先核对目标再恢复；账号退出清理个人内容缓存，账号切换使用各自的数据范围。草稿恢复时若目标消息已变化，显示当前正文与草稿，交由用户重新编辑确认。
5. 浏览器恢复可见、网络恢复或返回会话时，重新读取运行和保存结果。跨标签页操作通过重新读取发现；发现目标已删除、分支已变化或仍在运行时，保留本地输入并更新可用操作。
6. 流式接收、停止和写入恢复采用 S02。已取得正文可离线阅读，写操作等待连接恢复后的核对；原始输入和已保存消息分别处理。实际生成保存方式、分支激活与消息修订入口统一见[功能依据](../feature-basis.md)。
7. Runtime 加载或渲染失败时，通用导航与重试保持可操作；聊天写操作等待必要的角色状态就绪。普通资源重试与写入重试分别处理，写入结果遵循 S02。

## 8. 适配说明

1. 桌面顶栏在宽度不足时允许标题换行或截断，并提供可键盘访问的完整名称；返回、设置和人设入口保持可达。布局缩窄与放大时，角色内容需保持阅读与通用操作可用。
2. 键盘顺序为会话导航、运行反馈、角色可操作内容、消息列表及操作、输入区。菜单与弹层关闭后恢复触发焦点；正文更新保持当前焦点。输入标签说明扮演的人格姓名，账号昵称在本页承担账号标识时单独命名。
3. 状态采用礼貌播报，只播报生成开始、停止、失败及保存结果；逐段正文供阅读，流式字符更新保持安静。错误与禁用理由通过文本关联；控制状态同时使用语义属性。
4. 文字可选择、复制；浏览器原生右键菜单和快捷键保持可用。消息管理通过可见菜单完成。触屏桌面设备使用 `--size-target-min`、`--space-control-gap` 对应的点击区域与间距。
5. 长正文换行，长代码或表格在自身区域滚动；角色资源缺失显示可读替代文本。主题对比、焦点样式与文本放大在阶段 6、7 验收；手机布局见 [P18](page-P18.md)。

## 10. 特定场景微交互说明

1. **生成与停止**：行为采用第 4.2 节。运行反馈区保持固定的信息顺序，依次显示状态文字、可用操作和原因；停止按钮的按下反馈先于请求结果，使用户能够确认点击已被接收。
2. **阅读期间收到正文**：跟随条件采用第 4.1 节 C04。“回到最新”显示在列表边缘并为正文留出空间；用户主动滚动时中止正在进行的自动定位，控制权回到用户。
3. **切换候选**：行为采用第 4.3 节 C06。方向按钮与序号保持位置，正文区域承载读取反馈和内容替换；焦点停留在操作控件，便于继续比较。
4. 上述场景采用第 6 节 token；减少动态效果时直接呈现。声音与振动关闭；失败和结果待确认的恢复采用第 4 节对应条目。
