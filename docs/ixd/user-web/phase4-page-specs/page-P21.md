# P21：删除确认（桌面与手机 Web）

## 1. 页面概述

1. 本弹层属于通用反馈模块，沿用宿主页层级。入口为人格列表 P09／P10、历史列表 P15／P16、会话 P17／P18；取消及处理完成后回到发起页面。
2. 人格与历史删除分别采用[阶段 3](../phase3-userflows.md)的 F02、F05，消息删除采用 F04，结果核对采用 S02。
3. 本页目标是让用户核对删除对象及影响，并获得逐项明确的执行结果。删除能力及接入状态采用[功能依据](../feature-basis.md)。

## 2. 页面布局

1. 桌面使用居中对话框；手机使用底部对话框，长列表和大字场景下可占据可用视口。结构如下。

```text
删除对象标题
具体对象名称／消息摘录／已选会话数量
影响说明
所选条目（批量时可滚动阅读）
提交状态与逐项结果
取消或返回 │ 确认删除或处理剩余项
```

2. 对话框内部只让对象清单和说明区域滚动，底部操作区保持可见。手机操作区避开安全区域，正文末尾留出空间。背景宿主页暂停交互并保留原滚动位置。
3. 初次打开将焦点放在标题或取消按钮；标题与正文通过对话框语义关联。对象过长时允许换行，完整名称和影响范围可读取。

## 3. 组件清单

| 编号 | 组件       | 类型／位置             | 交互                               |
| ---- | ---------- | ---------------------- | ---------------------------------- |
| C01  | 目标与影响 | 只读内容／顶部         | 阅读对象及后果                     |
| C02  | 目标清单   | 只读列表／中部         | 阅读每个所选会话及其结果           |
| C03  | 取消或返回 | 次操作／底部           | 提交前取消，提交后回宿主页查看结果 |
| C04  | 确认删除   | 删除操作／底部         | 提交本次固定目标                   |
| C05  | 结果与核对 | 状态区域／底部或条目内 | 核对待确认结果、重试已确认未删除项 |

## 4. 交互行为详述

### 4.1 删除对象与确认内容

| 对象     | C01、C02 展示                                                | 确认按钮     | 完成后宿主页处理                                       |
| -------- | ------------------------------------------------------------ | ------------ | ------------------------------------------------------ |
| 单个人格 | 人格姓名、是否为默认；提示“已有演绎会保留各自保存的人设”     | 删除人格     | 重读人格集合及默认选择，规则引用需求规格第 3 节第 8 项 |
| 单个会话 | 会话标题、角色及人格姓名；提示“删除后无法继续此演绎”         | 删除演绎     | 从列表移除已确认删除的会话                             |
| 批量会话 | 明确数量、逐项标题及可区分信息；说明删除范围为当前已选条目   | 删除所选演绎 | 逐项更新列表及勾选结果                                 |
| 单条消息 | 说话者、正文摘录、目标所在位置；提示“删除这条消息后无法撤销” | 删除消息     | 重读当前分支记录及角色状态                             |

1. 表中消息删除采用[功能依据](../feature-basis.md#2-功能与数据来源)中的已保存内容修订入口。可执行目标由消息所在楼层与消息页状态决定；确认内容与实际单条删除操作一致。
2. 删除人格时，若目标是默认人格，额外显示按需求规格确定的后续默认姓名；最后一个人格则提示“之后开始演绎时，需要先创建人格”。会话内人格的展示沿用该会话快照。
3. 批量删除打开时固定当前已选目标和数量。若列表随后刷新，确认清单保持原目标；服务端执行结果逐项核对。目标信息读取不完整时先补齐可识别信息，再允许确认。

### 4.2 提交、取消与结果

1. **C03**：提交前点击取消、Esc、手机返回或对话框外部均关闭弹层并回到触发按钮。提交后按钮改为“返回列表”或“返回对话”；关闭弹层时宿主页继续承载待核对状态。
2. **C04**：只有目标明确且允许操作时可用。激活后固定本次目标、锁定重复确认，显示“正在删除…”。Enter 仅在按钮聚焦时执行该按钮动作；打开弹层时保留取消或标题焦点。
3. 单项成功后关闭弹层，宿主页显示“已删除”，焦点回到相邻条目；集合为空时回到空态主要入口。目标已不存在时刷新宿主页并提示“此项已不存在”。
4. **C02、C05**：批量结果按条目展示“已删除”“已不存在”“正在生成，暂时无法删除”“无法访问”等已确认原因。仅移除明确删除或已不存在项；其余项保留原因及处理入口。
5. 部分失败时显示已处理数量与剩余项，提供“返回列表”；需要重试时，C04 改为“重试剩余项”，仅提交明确未删除且当前允许执行的目标。结果待确认项通过“核对结果”读取。
6. 服务端拒绝且可修正时展示具体原因，保留原目标；运行冲突提示等待生成结束。响应缺失、断网或超时按 S02 核对，宿主页使用同一操作记录更新结果。
7. 所有按钮具有按下、悬停及焦点状态；删除动作通过明确动词、对象和视觉强调表达。辅助技术播报提交与最终结果，批量清单保留可逐项阅读的文本。

## 5. 页面状态流转

| 状态       | 进入条件                 | 展示与可用操作            | 后续                         |
| ---------- | ------------------------ | ------------------------- | ---------------------------- |
| 核对目标   | 宿主页发起操作           | 对象、影响、取消与确认    | 确认进入提交                 |
| 目标读取中 | 对象信息不足             | 局部读取反馈，确认不可用  | 成功后核对；失败可重试或取消 |
| 目标已失效 | 读取发现不存在或无法访问 | 具体结果与返回入口        | 更新宿主页                   |
| 提交中     | 删除已发出               | 固定清单、进度与返回入口  | 按实际响应处理               |
| 全部完成   | 全部已删除或已不存在     | 宿主页反馈处理结果        | 恢复列表或会话操作           |
| 部分完成   | 有逐项成功和失败         | 各项结果与剩余目标        | 返回或重试可执行项           |
| 明确失败   | 服务端拒绝               | 原因及仍可识别的目标      | 修正条件后再操作             |
| 结果待确认 | 响应缺失或关联不足       | 核对入口与返回入口        | 按 S02 重读                  |
| 身份失效   | 请求返回认证失效         | 关闭弹层并按 S01 登录恢复 | 重读目标及已有操作结果       |

## 6. 动效说明

1. 对话框出现与关闭使用 `--motion-duration-overlay`、`--motion-easing-standard`；提交及条目结果使用 `--motion-duration-feedback`。减少动态效果时直接呈现。
2. 宿主页在结果确认后移除对应条目，保持相邻条目的阅读锚点；删除中保留目标位置，便于用户辨认操作对象。

## 7. 数据策略

1. 打开时接收宿主页提供的账号、对象类型及目标标识。需要补读时按该归属读取；批量数量从固定目标集合计算，执行返回按同一集合逐项对应。
2. 单个对话框处理一种对象类型。删除请求中的真实权限与状态由后端判定；已有列表缓存仅用于展示确认信息。
3. 删除与结果核对由宿主页持续管理。对话框关闭、手机后台恢复或浏览器刷新后，宿主页先按 S02 恢复已有操作结果，再决定是否提供删除入口。
4. 批量结果处理采用第 4.2 节。重新读取失败时保留已确认结果及待核对项，避免用整批成功提示覆盖逐项差异。
5. 本弹层只显示本次已选目标。长清单按需呈现可访问条目，数量始终为完整所选集合；列表分页与搜索归宿主页。离线时可阅读已取得的确认内容，提交需等待连接恢复后核对目标。

## 8. 适配说明

1. 桌面支持 Tab、Shift+Tab 在弹层内循环，Esc 关闭；外部页面暂时退出焦点顺序。手机返回先关闭弹层，关闭后的目标位置采用第 4.2 节。
2. 手机对话框使用 `--size-target-min`、`--space-control-gap` 对应的点击范围和间距。窄屏、大字和横屏允许清单滚动，操作区保持可达；删除与返回各自拥有独立点击区域。
3. 标题标明目标类型，清单每项同时包含名称与结果。危险动作通过文本和语义标识表达；具体色彩对比、焦点样式及主题效果由阶段 6、7 验收。
4. 打开时收起宿主页键盘并保留输入；关闭后恢复触发焦点，键盘按浏览器行为处理。

## 10. 特定场景微交互说明

1. **确认与结果反馈**：行为采用第 4.2 节 C04、C05。按钮宽度在文字切换时保持稳定；批量清单在原条目位置显示进度和结果，方便用户逐项核对。
2. **取消与返回**：行为采用第 4.2 节 C03。覆盖层关闭后，焦点恢复位置采用第 4.2 节，并显示对应控件的焦点样式；宿主页的条目移除和阅读锚点采用第 6 节。
3. 两个场景采用第 6 节 token，减少动态效果时直接呈现；声音与振动关闭。请求失败与结果待确认采用第 4.2 节的恢复入口。
