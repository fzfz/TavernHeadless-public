# 两端原型的操作契约与验收路径

## 必须要实现的目标

设计 Agent 使用两个独立页面及其往返跳转验证[编辑边界](admin-web-interaction-boundaries.md)中的资源编辑、角色绑定、试聊维护和发布操作。管理端沿用现有三栏工作区，资源编辑使用中间宽区域；用户端通过唯一聊天页面承载正式演绎和管理员试聊，并支持选择角色、继续对话及历史管理。

管理端文件为 `apps/web/prototypes/admin-workspace.prototype.html`，用户端文件为 `apps/user-web/prototypes/user-roleplay.prototype.html`。管理端通过试聊入口打开用户端的指定会话，用户端通过返回入口打开管理端配置或生成详情。当前原型已迁移：管理端展示试聊记录，用户端承载聊天。页面内存中的创建、保存和生成结果用于操作设计；真实 API、持久化和跨页面同步按[两端实施方案](role-app-dual-web-plan.md)第二步起交付。

## 操作契约

以下 API 是正式实施时的对应关系。带“拟新增”的路径属于两端方案的待实现契约。原型使用符合接口结构的场景数据展示跳转与操作；真实交接与持久化按主计划第二步验收。

| 操作入口                             | 对象、输入与写入时机                                              | 正式后端对应                                                                                        | 成功、失败及后续操作                                                                                       |
| ------------------------------------ | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 角色导航、试聊列表、试聊状态         | 读取已保存的试聊与当前选择                                        | `GET /sessions`，补充应用与试聊用途筛选；拟新增 `/role-apps/:id/preview-sessions` 查询              | 继续试聊跳转用户端已有会话；导航保持记录数不变，无记录显示开始入口                                         |
| 开始试聊、新建独立试聊               | 提交已保存的草稿修订，创建独立 session                            | 拟新增 `POST /role-apps/:id/preview-sessions`，复用会话创建服务                                     | 获得 ID 后加入列表并打开用户端试聊；配置未保存或缺项时返回配置入口；继续、改名、归档、恢复和删除管理该记录 |
| 发送、重试回复                       | 向当前 session 提交消息；重试引用失败楼层                         | 现有 respond/stream 与楼层 retry 能力，由角色应用适配层调用                                         | 展示生成中、完成或失败；重试保持已提交消息数量不变                                                         |
| 试聊改名、归档、恢复                 | 提交名称或 active/archived 状态                                   | `PATCH /sessions/:id`                                                                               | 成功后更新列表和详情；归档保留记录，恢复后继续发送                                                         |
| 删除试聊                             | 删除指定 session 及其消息记录                                     | `DELETE /sessions/:id`                                                                              | 生成中保留记录并解释原因；删除成功后移出列表，最后一条删除后显示空态                                       |
| 资源库、选择资源                     | 读取资源列表；选择只修改绑定编辑草稿                              | 已有角色、预设、世界书、正则、Profile 和 `/users` 列表及详情接口                                    | 显示资源及可选版本；选择结果仍需保存角色草稿                                                               |
| 新建资源、复制资源                   | 打开独立编辑草稿，保存时创建新 ID；复制以已有内容初始化           | 角色创建、`POST /import/preset`、`/import/worldbook`、`/import/regex`、Profile 创建及 `POST /users` | 保存后加入资源库；取消放弃编辑；已有对象提供编辑和删除                                                     |
| 导入 JSON                            | 读取所选文件到对应资源编辑器，检查后保存                          | 正式实现由已有 import 解析器校验和创建资源                                                          | 解析失败提示重新选择该类型文件；读入成功尚未创建资源，管理员可以取消                                       |
| 编辑、新增条目、删除条目、上移、下移 | 修改资源编辑草稿；保存资源时提交整份文档                          | 预设 editor/PUT、世界书和正则 PUT；角色版本、Profile 和人设更新接口                                 | 保存后形成资源新版本或新配置内容；取消保留原资源；冲突保留编辑内容并提示重新读取                           |
| 保存模型、调整 Temperature           | Profile 编辑 provider、地址和模型；角色草稿维护 narrator 实例参数 | `llm-profiles` 与 `llm-instances`，拟新增角色应用草稿解析                                           | 两类配置分别保存；试聊详情和发布配置显示选用模型及实例参数                                                 |
| 删除资源                             | 删除所选资源，先检查角色草稿、发布和试聊引用                      | 各资源 DELETE；角色应用引用查询和保护需补齐                                                         | 被引用资源显示具体对象并保留；未引用资源删除成功后移出资源库                                               |
| 导出                                 | 导出所选角色、预设、世界书或正则内容                              | 正式实现复用后端导出能力或 SDK 的资源文档                                                           | 文件交给浏览器下载；资源列表保持不变                                                                       |
| 保存草稿、撤销修改                   | 提交或放弃角色绑定和实例参数的未保存修改                          | 拟新增角色应用 draft 接口                                                                           | 保存后修订号增加，旧试聊配置保持不变；缺项或参数越界时保持输入可编辑                                       |
| 发布新版本、停止发布、切换到指定版本 | 发布已保存修订，或切换当前发布指针                                | 拟新增 releases 与 publication 接口                                                                 | 新对话使用当前发布；旧对话保持原配置；未保存配置先回到配置页处理                                           |
| 试聊详情、查看发布配置               | 读取创建或发布时的配置快照                                        | session 关联查询、拟新增 release 详情                                                               | 显示固定修订、资源引用、模型和参数；变量与记忆按此角色的启用状态显示                                       |
| 查看配置位置                         | 查看低频部署参数的文件位置和生效方式                              | `.env.example`、`apps/api/src/config.ts`                                                            | 维护者根据部署方式修改环境变量并重启服务                                                                   |
| 用户开始或继续对话                   | 没有历史时创建，有历史时默认继续；新对话单独创建                  | 拟新增 runtime 会话创建、列表、详情和 timeline                                                      | 停止发布关闭新建入口，已有历史可以继续                                                                     |
| 用户改名、删除                       | 修改或删除自己的指定会话                                          | 拟新增 runtime session PATCH/DELETE，复用会话服务并检查使用者归属                                   | 删除最后一条回到角色入口；生成中提示完成后删除                                                             |
| 用户发送、重试                       | 提交用户消息，重试失败回复                                        | 拟新增 runtime respond、stream 和楼层 retry 适配                                                    | 原输入保存为一条消息，失败重试只新增回复结果                                                               |

资源 ID、修订号和发布记录都来自本页内存。Profile 与人设的“配置快照”用于表达角色创建时固定的内容；正式实施将这些内容保存到角色应用或会话快照，现有 Profile 与人设 API 本身没有因此新增资源版本接口。

逐页字段、导演与 Agent 的核对以[管理端逐页字段与操作核对](admin-editor-page-audit.md)为准。

## 原型覆盖范围

资源编辑器覆盖角色描述、性格、场景、开场白和示例对话；预设正文、角色、启停和注入位置；世界书关键词、正文及常用开关；正则查找、替换、执行位置、通道、消息深度和顺序；模型基本连接字段；演绎人设描述。每类资源均提供新建、复制、编辑和删除。文件导入导出提供 JSON 操作入口，正式格式校验与完整扩展字段处理由仓库已有解析器承担。

演绎运行配置提供全部五个 LLM 槽位、生成参数、工具能力和回合流程。LLM Profile 提供凭证更新、模型发现和测试入口；工作区 Agent 类型、项目绑定与任务管理分别提供页面，字段及接口边界引用逐页核对文档。

两页的演绎回复使用内存场景。管理页使用仓库正则引擎和世界书触发引擎计算处理结果与激活记录；真实模型表现、最终提示词插入及跨页面发布同步由正式联调验证。模型发现和连接测试使用示例响应；Agent 任务示例停留在排队状态并支持取消。

## 验收清单

验收者从管理端开始执行以下流程，消息操作在跳转后的用户端完成：

1. 打开页面，确认已有“港口书店 · 灯塔来信”试聊；切换导航并再次选择同一记录，确认数量不变。明确新建独立试聊后，列表增加一条记录。
2. 发送消息，在生成中尝试删除，确认记录保留；完成后改名、归档、恢复，再删除新建记录并确认原有试聊仍在。
3. 新建预设，在保存前增删和排序条目；取消编辑后确认资源列表不变。重新新建并保存，确认独立资源加入列表。
4. 编辑已绑定预设并保存，核对角色草稿显示的资源版本；选择新版本并保存角色配置，确认原试聊修订保持不变，明确新建试聊后使用新修订。
5. 修改角色开场白并保存、绑定新版本，新试聊显示新的开场白。修改 narrator 的 Temperature 并保存，在试聊详情核对该参数。
6. 删除未被引用的副本，再尝试删除已发布资源，确认后者显示具体引用位置。
7. 发布保存的草稿，查看发布配置；停止发布，再选择历史版本重新发布，核对当前发布标记。
8. 完成配置修订对照后，删除已结束的剩余试聊，观察空态。

验收者在用户端先开始对话，再回到角色介绍点击继续，确认历史数量不变；明确新建另一段对话，分别改名和删除，最终回到无对话状态。

异常场景通过文件 URL 的查询参数选择，页面内保持正常产品入口：

| 页面与参数                         | 验收操作                                     | 完成条件                                                     |
| ---------------------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| 管理端或用户端 `?scenario=failure` | 开始对话，发送一条消息，等待失败，再重试回复 | 原消息保留一条，重试成功后增加一条回复                       |
| 用户端 `?scenario=stopped`         | 从角色入口继续既有对话，再检查新建入口       | 既有对话可继续；新建入口关闭并显示原因                       |
| 用户端 `?scenario=updated`         | 继续既有对话，再新建一段对话                 | 原记录保持旧发布关联，新记录使用新发布；用户无需重新配置角色 |

原型源代码检查覆盖脚本语法与内存状态变化；真实布局、键盘操作、窄屏效果和浏览器交互由页面操作验收。正式代码测试要求引用两端实施方案的验收清单。

## 状态栏与显示正则的补充验收

管理端原型已经包含两套正则、两本世界书、三轮完成回复和一个可重试失败轮次。管理员在用户端从消息跳转管理端生成详情，在“正则与显示结果”查看原文、规则顺序、本轮变量和渲染结果；在正则编辑器调整规则并查看处理结果。具体场景以[状态栏方案](role-status-rendering.md)为准。设计 Agent 必须在用户端原型补齐同一状态栏的多轮变化、加载与失败布局，按主计划第一步提交整体验收。

当前原型使用 `apps/web/prototypes/shared/workspace.prototype.js` 中的同一消息处理与渲染实现，`navigation.prototype.js` 负责两页跳转及界面入口；管理端展示记录，用户端展示聊天。试聊上下文、返回配置和按消息查看生成详情的跳转已接通。验收者来回切换后核对会话及消息标识，确认操作既有会话且原功能均有可达入口。

两页通过当前浏览器窗口的 `window.name` 传递同一内存场景，保留资源、配置、会话、轮次及消息位置。新窗口独立加载初始场景。原型在页面切换后继续已有生成执行，保持执行标识和用户消息数量；正式交接凭据及后端运行恢复仍按主计划第二步实现。
