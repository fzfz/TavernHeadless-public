# 角色卡编辑入口统一

状态：2026-09-29，用户明确要求管理端和用户端统一采用新角色包格式。角色编辑入口替换和真实浏览器验收已完成，代码规范及需求符合性独立审阅通过。

## 必须要实现的目标

管理端负责人保留管理 Web 的导航布局、预设、模型、世界书、正则、演绎人设及运行管理功能，将现有“角色卡”“管理角色卡”“编辑角色卡”入口统一接入新版角色卡编辑器。角色卡目录负责新建、ZIP 导入及继续编辑；旧角色 JSON 表单及其编辑、导入、导出调用从管理端资源编辑模块中移除。

产品界面将角色称为“角色卡”，制作页面称为“角色卡编辑器”，导入文件称为“角色包 ZIP”；工具栏保留批准原型的“导入 ZIP”按钮，弹窗明确说明角色包用途。编辑器地址为 `/character-editor`。前端通过角色包记录的 `characterId` 打开同一角色的编辑目录；发布配置和用户端继续使用这个角色 ID 及固定版本。

主 Agent 核对角色包的工作目录、保存修订、角色版本和发布记录的关联，并通过真实浏览器完成“管理端角色卡入口 → 编辑保存 → 发布 → 用户端角色列表 → 创建会话”的验收。角色包文件规则、ZIP 校验和持久化接口沿用[角色包方案](native-card-package.md)；源码和 API 中现有的 `native-card` 标识属于内部实现名称。

已有会话保留固定版本，已有数据保持可读取。已删除或没有关联角色包的历史配置保留绑定，界面说明当前无法编辑，并提供新建或导入角色包的操作；新绑定只列出可用且关联角色包的角色。外部旧格式由独立转换器产生角色包 ZIP 后导入。
