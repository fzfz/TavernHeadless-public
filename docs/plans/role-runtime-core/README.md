# 按 API 文档实施角色运行核心

## 必须要实现的目标

执行团队按角色卡 JavaScript API、后端 API 和 Agent 工具 API 实现原生角色包及编辑器。角色卡、角色前端、系统前端、后端和 Agent 必须符合相应文档规定的调用方法和执行逻辑。执行者先核对方法契约，再完成实现，并用正式页面和实际后端验收。

本轮交付是正式原生 ZIP 导入、编辑、保存、固定版本发布、会话运行、打包下载和独立环境再次导入，以及对应 API 文档和逐项可复核的验收记录。编辑器采用已批准原型的视觉与交互基线。

## 执行入口

1. 阅读[角色 JavaScript API](../../character-authoring/script-api.md)、[后端 API](../../character-authoring/backend-api.md)和 [Agent 工具 API](../../character-authoring/agent-tools-api.md)，核对调用双方、参数、返回、回调和错误。
2. 阅读 [ZIP 角色包与单文件迁移方案](native-card-package.md)，核对世界书、包内文件、解包运行和继承关系。
3. 阅读 [原生角色卡编辑器方案](native-card-editor.md)，核对页面、文件与表单操作、保存、预览和交付。
4. 阅读 [正式管理端联调计划](native-card-production-integration.md) 和 [原生包接口](native-card-io.md)，按 I01–I15 核对实际存储、编辑、发布、运行与 ZIP 往返。

角色卡 JavaScript API 文档统一记录方法参数、返回、回调、错误和角色脚本示例。执行者在 script-api.md 中修改方法定义，并同步对应角色脚本与验收示例。OpenAPI、schema 和自动生成类型分别承担结构检查和工具接入，开发者阅读的 API 文档必须完整交付。

## 验收清单

- 执行团队同步受影响的 API 文档，明确调用双方、参数、返回、执行顺序、失败行为和页面效果。
- 角色卡的每项运行能力能对应到文档中的 API；后端持久状态由文档规定的服务端调用提交。
- 用户能选择开场、发送输入、看到流式正文和提交后的状态，回看历史并恢复最新画面。
- 原生包文件及引用由共享 schema 和文件规则定义；后端在写入、发布和打包前统一校验。
- 每阶段按可见验收步骤保存页面、操作和对应请求结果；文档、原型和实际调用一致。

## 非本次目标

当前授权范围包括原生角色包及编辑器的正式前后端实现和相关运行接入。独立转换器、完整插件宿主、115 张卡全部迁移、正式部署和账户体系另列任务。每项完成状态只证明其列明并已验收的能力。
