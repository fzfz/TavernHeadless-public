## 提示词组装修复

`apps/api/src/services/prompt-assembler.ts` 原先在预设与历史合并后执行输入正则，并按消息正序索引计算深度。深度为零的规则因此可能处理预设中的 user 片段，实际当前输入却落在 `<最新互动>` 标签外。dry-run 又在该处理前返回，导致检查结果与真实发送内容不同。

修复后，输入正则先作用于真实对话中的用户消息，深度从最新对话消息的零开始计算，再插入预设并合并消息。世界书触发仍读取原始对话。dry-run 和发送流程使用同一份处理结果。[SillyTavern 正则文档](https://docs.sillytavern.app/extensions/regex/)说明深度从最后一条对话向前计数，并将系统及辅助提示排除在该深度范围之外。

`apps/api/test/model-calls.integration.test.ts` 新增九个回归场景，覆盖三种组装模式、当前及历史用户消息、预设辅助片段、姓名前缀和世界书关键词替换；测试逐条比较 dry-run 与截获的实际请求消息。四个相关测试文件共 83 项通过，API 和管理端构建、ESLint 检查通过。

这证明先前的实际请求存在组装缺陷。此前正文缺失、重复或主体混乱的具体原因仍需基于修复后的请求分别复验；旧样本保留为历史观察。

最终全量回归执行 `pnpm exec vitest run --reporter=dot`，472 个测试文件、4,200 项测试全部通过。验收结束后，三个本机服务已停止，43980、43981、43982 端口均已关闭。
