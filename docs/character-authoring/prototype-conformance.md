# 角色附加模板与交互契约验证

## 必须要实现的目标

本次验证角色作者能否仅依照[模板规范](template-api.md)与[交互 API](interaction-api.md)创建不同布局，并通过逐轮提交的数据改变布局、状态与动作。解释器位于 `apps/web/prototypes/shared/card-runtime.prototype.js`，共享校验与表达式执行位于 `card-contract.prototype.js`。

## 角色包检查

服务读取 `characters.seed.prototype.json`，将两张角色卡经真实角色版本接口写入独立内存 SQLite。浏览器只从角色接口读取 `card_view`。这两张角色包已移除旧 presentation 字段；旧 HTML 原型的聊天基础配置仅用于模拟器内部接线，角色作者按新契约提供包即可。

| 对象                   | 林岚                                                 | 岑宁                               |
| ---------------------- | ---------------------------------------------------- | ---------------------------------- |
| 页面结构               | 场景与聊天分栏                                       | 场景、阅读正文、控件和输入纵向排列 |
| 数值字段               | trust                                                | courage                            |
| 初始值、第一轮、第二轮 | 10 → 35 → 75                                         | 10 → 35 → 75                       |
| 布局条件               | expanded 改变左右列宽                                | expanded 添加正文侧边强调样式      |
| 背景                   | 书店 → 港湾 → 书店                                   | 港湾 → 港湾 → 书店                 |
| 状态与选项             | 地点、线索、进度条更新；数值达到 30 后显示“查看线索” | 同一机制读取另一套变量声明         |
| 画廊                   | gallery 数组从一张图变为两张                         | 同一 repeat 节点机制               |

两个包都使用同一套 box、text、image、meter、button、repeat 和 slot 节点。节点树和 CSS 定义布局，条件与动作声明定义交互，运行时通过同一解释路径执行。第三种排列通过角色版本接口提交修改后的包，将根布局改为反向纵向排列；浏览器重新选择角色后显示该排列，随后验证脚本将角色配置恢复。

## 数据与调用边界

真实后端验证覆盖角色版本的保存、读取及包的传输。逐轮回复和变量来自 `card-turns.fixture.json`，由隔离 `/prototype-runtime/respond` 服务按契约提交。该服务读取固定角色版本、检查 expectedSnapshotId、解析 actionId 对应的指令并校验完整变量值。

用户按钮和输入框调用同一个 send 控制器。新增生成适配器将控制器请求发送到隔离响应桩；已有其他原型会话继续使用原生成模拟器。正式 LLM、事务提交、权限和分支持久化未在本轮实现。

## 验收清单

运行 `checks/card-contract-unit.mjs <已安装 Ajv 入口>` 校验两张角色包及逐轮变量，同时检查无效节点、动作、变量、资源和请求参数。该脚本位于 `apps/web/prototypes` 下。运行 `checks/card-contract.mjs <已安装 Chromium 可执行文件> <隔离服务 origin>` 执行浏览器与 HTTP 验证。

| 验收项                       | 结果与证据                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| 两张角色卡符合同一 schema    | 通过；独立 Ajv 校验与浏览器/服务共用校验器结果一致                                  |
| 每轮变量改变状态、图片和布局 | 通过；两张卡均验证 10、35、75 与 expanded 条件变化                                  |
| 当前动作与历史显示分离       | 通过；回看初始状态显示 10，当前选项仍显示第一轮的指令；第二轮提交后回看位置保持不变 |
| 本地阅读与媒体动作           | 通过；面板开关、翻段、自动阅读、跳至最新和音乐播放/暂停均已执行                     |
| 服务端校验                   | 通过；发送类以外的动作被拒绝，超出声明范围的轮次变量被拒绝                          |
| 动作草稿行为                 | 通过；send 保留未发送草稿，fill 覆盖草稿并保持轮次数不变                            |
| 过期提交与失败提交           | 通过；过期快照返回 409，结果耗尽时返回失败且前端保持旧快照                          |
| 新排列不修改解释器           | 通过；第三种组合由后端角色版本返回                                                  |
| 手机与系统控件               | 通过；390px 页面无横向溢出，输入控件保持唯一                                        |

机器证据为 [schema-report.json](../plans/evidence/card-contract/schema-report.json) 和 [report.json](../plans/evidence/card-contract/report.json)。视觉证据为 [林岚第一轮](../plans/evidence/card-contract/card-bookshop-turn1.png)、[岑宁第一轮](../plans/evidence/card-contract/card-novel-turn1.png) 和 [第三种排列](../plans/evidence/card-contract/third-composition.png)。

## 非本次目标

作者契约 v1 已有可执行原型。正式后端的显示事务与历史查询、媒体托管、用户鉴权和完整分支恢复仍按开发计划实施。管理端现有显示编辑器仍编辑前一轮配置；新增 card_view 的正式表单与发布预览需要按这两份 API 文档接入。原型内的角色包当前由 JSON 文件编写并通过真实版本接口保存。

## 已获得的授权

用户要求先建立作者规范，再对照规范改造原型，并验证不同角色卡及每轮变量驱动的布局和交互。隔离验证沿用已授权的本地服务方式及现有依赖，没有安装新依赖。
