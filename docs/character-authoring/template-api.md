# 角色卡附加模板规范 v1

> 本文保留旧 v1 原型契约，供核对既有实现。新的目标架构改用角色 JavaScript，作者规范见[模板与入口](script-template-api.md)及[脚本 API](script-api.md)。本文 actions/completion 不再作为新版作者接口。

本版职责与后续扩展边界见 [角色 Runtime 架构](runtime-architecture.md)。未来游戏玩法用于检查模块扩展可能，其业务模型按具体需求另行设计。

## 必须要实现的目标

角色作者在角色版本的 `snapshot.extensions.tavern_headless.card_view` 中提供附加模板。系统使用同一个解释器加载所有角色；角色作者通过节点树、CSS、字段绑定和条件表达布局。本规范定义新增能力，实施边界见“非本次目标”。

基础角色包结构由 `apps/web/prototypes/shared/card-contract.schema.json` 定义；新增 completion 契约的结构与接入状态见交互 API 的“调用、返回值与结果处理”。动作语义见[交互 API](interaction-api.md)。两份文档供角色作者设计新角色卡，后端使用 JSON Schema 和引用检查完成包校验，管理端使用同一结构提供编辑提示。前端接收后端组装的渲染数据，职责边界见[模块架构](runtime-architecture.md#模块架构)。

## 附加包结构

| 字段         | 含义                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `apiVersion` | 固定为 1；系统按版本选择契约                                                                                                |
| `title`      | 角色演绎页面标题                                                                                                            |
| `variables`  | 变量声明，键为完整变量名，值声明 string、number、boolean 或 array 类型；数值可声明 minimum、maximum                         |
| `initial`    | 初始变量全量值；所有声明变量均需提供                                                                                        |
| `avatar`     | 系统历史消息使用的角色头像资源标识，引用 assets                                                                             |
| `ui`         | 本地显示状态的初始值，当前支持布尔值，例如状态面板和历史面板的开关                                                          |
| `assets`     | 资源标识到文件的映射；kind 指定 image 或 audio，file 指定包内相对文件路径；图片支持 SVG/PNG/JPEG/WebP，音频支持 WAV/MP3/OGG |
| `css`        | 角色内容区的样式，节点通过 class 引用；系统导航和会话操作位于内容区之外                                                     |
| `tree`       | 递归节点树，布局由作者自行组合                                                                                              |
| `actions`    | 动作标识与声明的映射，字段和执行规则见交互 API                                                                              |

角色布局由节点组合与 CSS 定义，系统按节点类型与动作类型执行；CSS Grid、Flex、绝对定位和手机断点由作者配置。节点类型与动作类型属于系统提供的有限能力集合，新增能力需要同步契约版本、校验器和解释器。

## 作者使用步骤

1. 作者在角色版本中新增 card_view，填写 apiVersion、title、avatar、assets、变量声明和 initial；角色姓名与开场白继续填写角色 snapshot 的 name、first_mes。
2. 作者用 tree 组合节点，为需要变化的节点填写 value、when 或 classWhen，并用 css 定义布局及手机断点。
3. 作者在 actions 中声明按钮动作，并将按钮 action 指向该标识。动作参数和当前状态限制按交互 API 配置。
4. 作者通过管理端提交角色包，由后端完成 schema 校验与引用校验并保存角色版本，然后在同一用户 Web 中试聊，分别观察初始、提交成功、历史回看和失败画面。

可直接阅读 `apps/web/prototypes/shared/characters.seed.prototype.json` 中的两份完整角色包。下面的节点使用角色自己声明的 courage 字段，并在达到 30 时显示提示：

```json
{
  "id": "courage-note",
  "type": "text",
  "value": { "source": "literal", "value": "可以继续探索了" },
  "when": {
    "op": "gte",
    "left": { "source": "view", "key": "courage" },
    "right": { "source": "literal", "value": 30 }
  }
}
```

completion 属于已定义但尚未接入原型的新增契约。动作完成后的本地交互通过 actions 中的 completion 字段声明，语法与执行语义见[交互 API 的调用与结果处理](interaction-api.md#调用返回值与结果处理)。

## 节点与绑定

每个节点必须提供唯一 `id` 和 `type`，可提供 `class`、`when` 和 `classWhen`。`when` 为假时节点隐藏；`classWhen` 将类名映射到条件，条件成立时添加该类。布局尺寸与排列通过这些类对应的 CSS 改变。

| type     | 字段与效果                                                                |
| -------- | ------------------------------------------------------------------------- |
| `box`    | `children` 定义子节点，可任意嵌套                                         |
| `text`   | `value` 的结果作为纯文本显示                                              |
| `image`  | `value` 返回 assets 中的资源标识，`alt` 提供替代文字                      |
| `meter`  | `value` 返回数值，`min`、`max` 定义显示范围；系统将显示比例限制在此范围   |
| `button` | `value` 为按钮标题，`action` 引用动作 ID；系统根据动作权限决定是否禁用    |
| `repeat` | `value` 返回数组，`children` 对每个成员重复绑定；成员在 item 作用域内可读 |
| `slot`   | `name` 为 history 或 composer；系统将唯一消息历史和输入组件挂入该位置     |

每张角色卡必须各提供一个 history 和 composer 插槽。作者可将历史放入可展开面板，但必须提供打开它的动作按钮。系统保留外层会话操作，正文、头像和历史消息操作由系统消息组件提供。重复节点里的 id 是模板局部标识，实例以数组索引区分；作者通过树节点定位编辑目标。

值表达式采用 `{ "source": "view", "key": "trust" }` 或 `{ "source": "literal", "value": "当前状态" }`。

| source    | 可读数据                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `view`    | 正在回看的显示快照变量                                                                                                       |
| `current` | 当前分支最新提交快照变量，用于当前行动选项                                                                                   |
| `ui`      | 卡内本地显示状态                                                                                                             |
| `read`    | `text` 为当前阅读段落，`index` 为从 0 开始的段落序号，`count` 为段落总数，`auto`、`music` 分别表示自动阅读和音乐是否正在播放 |
| `item`    | repeat 当前成员的指定属性；省略 key 表示整个成员                                                                             |
| `literal` | value 中的字符串、数值或布尔常量                                                                                             |

变量 key 按完整字符串读取，例如 `scene.location` 就是一个键。条件支持 eq、ne、gt、gte、lt、lte 比较，以及 and、or、not 组合；eq/ne 采用类型和值同时比较，大小比较要求两侧均为数值，类型不符时条件为假；字段格式由 schema 定义。图片 value 可以绑定变量，因此每轮提交能够改变背景、立绘和头像以外的展示图片。角色与演绎者头像仍由系统历史身份记录提供。

## 每轮更新与历史

初始画面使用 initial。后端在提交前校验全部变量，成功提交后提供全量变量快照；前端据此更新绑定、条件、列表和样式类。生成中及失败时保留上一次成功提交的显示快照。变量只通过成功提交改变，ui 开关只改变本地显示。

默认回看指针跟随最新提交。使用 history.prev 回看后，新回复到达时保留正在查看的旧记录；history.latest 恢复跟随。当前行动选项使用 current，与 view 分开。切换分支时应读取目标分支的快照序列并重置回看位置，分支读取接口归“非本次目标”所述正式后端工作。快照保存变量值与角色模板版本，新角色版本用于新会话。

## 验收清单

实施者必须校验两张角色卡的包结构、节点与资源引用，并逐轮检查文本、数值、图片、条件显隐、列表和布局类变化。验收者必须增加第三种布局组合，保持解释器代码不变。检查必须包括历史回看保持旧值、当前选项保持最新值、失败提交保持已提交画面，以及桌面和手机视口。

## 非本次目标

v1 提供本文定义的节点与表达式。任意角色 JavaScript、自由网络请求、拖拽搭建器、持久化 CG 解锁和段落级导演事件留作独立契约扩展。正式媒体存储和正式显示快照接口仍需产品后端实施；隔离原型的响应桩用于验证本规范。

## 已获得的授权

用户要求先设计未来角色卡可使用的附加模板和交互 API，再检查两张角色卡是否符合规范，并实际验证每轮变量变化后的布局与状态变化。用户已授权在独立 worktree 中修改原型并启动隔离验证服务。
