# 模型调用历史先于请求发送持久化

生成追溯必须保留失败调用当时的真实请求。模型调用模块必须在供应商请求发送前等待请求记录保存成功，在调用结束后保存响应或错误；持久化层必须先按适用策略重试数据库写入，再将最终失败沿生成服务和接口错误链向上传递。数据库写入重试必须复用原调用标识并仅执行保存动作。

`packages/core` 必须通过注入的记录接口等待保存结果，`apps/api` 必须提供数据库实现和查询服务。调用历史必须采用独立于正文提交事务的记录，使正文提交失败后仍能读取已发生的模型调用。该选择使调用记录的持久化成为生成的前置条件，并增加请求发送与结果交付的写入等待时间。

后端必须分别表达模型调用结果、调用记录保存结果与轮次提交结果。供应商失败必须保留原始错误；保存同一失败结果再次出错时，错误链必须同时保留这两个原因。历史查询必须按已保存证据表达完成情况。首批接入路径、契约与验收由[首批实施细则](../plans/generation-trace-batch-1.md#首批实施细则)定义。
